# 01 · 项目电梯演讲与简历映射

> 面试官对项目介绍的第一反应，决定了他后面 40 分钟追问的方向。
> **你要做的是"引导"——把他的注意力引到你最硬的那块地上。**

---

## 一、30 秒版（自我介绍末尾 / 面试官说"简单介绍一下"）

> 我做的这个项目叫 AIHub，是一个**多租户的 AI 能力中台**。
> 它解决的是"企业里多个业务方想用大模型，但模型、知识库、工具、用量都得各搞一套"的问题——
> 我把这些收敛成一套中台能力：**模型可换、知识可插、工具可注册、Agent 可编排**，
> 并且所有调用都按租户计量和审计。
>
> 技术上是 Java 17 + Spring Boot 3.5 + Spring Cloud Alibaba + Spring AI 1.1.5 的微服务，
> 9 个 Maven 模块，前端有 Vue3 管理后台和 uni-app 的 H5/小程序双端。
>
> 我最想讲的是三块：**Agent 内核的预算控制与可中断**、**RAG 的引用可回溯**，
> 以及**多租户隔离与配额体系**。您想先听哪一块？

**为什么这么设计结尾**：给面试官一个选择题。他选哪块，你后面就讲你最熟的那块。
这三块恰好对应三条技术主线（Agent / RAG / 工程架构），覆盖 Java、Agent、全栈三个岗位的核心考点。

## 二、1 分钟版（"展开讲讲"）

在 30 秒版基础上补三句话：

1. **架构上做了一个关键决策**：AI 相关的能力（对话、RAG、工具、Agent）**内聚成一个服务**，
   而不是拆成对话服务 / 知识库服务 / Agent 服务。原因是这三个难题会被放大：
   分布式事务、流式响应跨服务传递、Agent 跨服务编排。
   服务间只留"租户校验 / 配额扣减 / 审计上报"三类**无事务**调用。

2. **工程质量用构建期卡口保证**：分层是 `web → application → domain ← infra`，
   domain 层零框架依赖，Spring AI 的所有类型被限制在 `infra.ai` 包内。
   这些不是口头约定，是 **ArchUnit 在 `mvn test` 阶段强制校验**的 4 条规则，
   写错就构建失败。

3. **Agent 部分我做的是"能上生产"的约束**：任务规划 → 按名派发 → 子 Agent 执行 → 产物落盘。
   加了**三重预算**（子任务数 3 / Token / 超时 180s）防止跑飞，
   支持**服务端真正可中断**，任务和每一步都落库可回放。

## 三、3 分钟版（技术面开场，最常用）

按这个结构讲，**每段留一个"钩子"让面试官打断你**：

### 第 1 段：背景与问题（20 秒）
企业接大模型时的四个痛点：模型供应商要能换（不能绑死一家）、知识库要能按租户隔离、
工具要能扩展、花了多少钱要能算清。

### 第 2 段：整体架构（40 秒）
网关（8080）做 JWT 鉴权 + Sentinel 限流 + 路由；平台服务（8081）管租户、配额、审计、API Key；
AI 服务（8082）承载全部 AI 能力。底层 MySQL 两个独立库（platform / ai）、Redis Stack（向量）、
Nacos、Sentinel。
前端两套：Vue3 + Element Plus 的管理后台，uni-app 的 H5 + 微信小程序。

> **钩子**："为什么 AI 能力不拆开？这是个我有意为之的决策——"

### 第 3 段：AI 服务内部（60 秒，重点）
- **模型层**：OpenAI 兼容协议适配多家（openai / 火山方舟 / 通义 / deepseek），
  按场景选模 + 主备降级；ChatClient 工厂按 `租户:应用:场景:模型` 四段 key 做 60 秒 TTL 缓存，
  用 `ConcurrentHashMap` + 双重检查锁。
- **RAG**：上传 → 解析（PDFBox 3.0.3 / POI 5.3.0）→ 分片（500 字，重叠 100）
  → 向量化 → Redis Stack 检索（topK 4、阈值 0.6、强制 `tenant_id` 过滤）。
  回答带 `[n]` 引用，引用落库**刷新页面后还能查回来源**。
- **Agent**：PlanningAgent 拆任务 → AgentRegistry 按名派发 → Table/Chart/HtmlDoc/Browser 四类子 Agent
  → 产物落盘可预览。全程 `agent.step` 事件流，三重预算 + 可中断 + 步骤落库。
- **工具与 MCP**：内置工具 + MCP Client 接入外部工具；反过来 AIHub 自己也能当 MCP Server，
  用一套 `@Tool` 实现同时提供 SSE、stdio、streamable-http 三种传输。

### 第 4 段：工程质量（40 秒）— 这段是给 Java 岗加分最多的
- 多租户：租户 ID 只从 JWT 解析，网关**先删后写**头部防止伪造；
  检索出口还有 `TenantGuard` 逐条校验。
- 配额：四个维度（request/token/doc/task），
  扣减走 `insert ... on duplicate key update used_value = used_value + #{amount}`，
  靠唯一键保证原子累加。
- 可观测：TraceId 贯穿网关→Feign→MDC→响应体；Micrometer 指标 + Prometheus + Grafana 仪表板；
  指标标签只放低基数枚举，**绝不放 tenantId**（否则时序库被租户数放大）。
- 密钥：模型 Key 用 AES-GCM 加密落库；开放 API Key 只存 HMAC-SHA256，明文仅签发时出现一次。

### 第 5 段：收尾（20 秒）
"这个项目里我印象最深的是几个坑：MCP stdio 下 stdout 被 banner 污染导致客户端一连上就崩；
浏览器 Agent 的页面标注残留导致点空。**如果您感兴趣我可以展开讲讲排查过程。**"

> **钩子**：主动给出"讲坑"的入口——坑比功能更能证明你是真写的。

## 五、简历条目：从"课程作业腔"改到"工程腔"

### ❌ 改写前（典型问题：只写用了什么，没写解决了什么）

> 项目描述：基于 Spring Boot + Spring Cloud Alibaba 的 AI 中台项目，
> 使用了 Spring AI、Redis、MySQL、Nacos、Sentinel 等技术，实现了对话、知识库、
> Agent 等功能。

**问题**：这是"技术名词堆砌"，看不出任何难度和你的判断力。

### ✅ 改写后（Java 后端岗版）

> **AIHub 多租户 AI 能力中台**（Java 17 / Boot 3.5 / SCA / Spring AI 1.1.5）
> - 设计"AI 能力内聚为单服务"的微服务边界，规避分布式事务、流式跨服务传递、Agent 跨服务编排三类难题；服务间仅保留租户校验 / 配额扣减 / 审计上报三类无事务调用。
> - 以 ArchUnit 将 `web→application→domain←infra` 分层固化为构建期卡口（4 条规则），domain 层零框架依赖，Spring AI 类型收敛于 `infra.ai` 包，跨层违规直接构建失败。
> - 实现四维配额（request/token/doc/task）硬限流：基于唯一键的 `INSERT ... ON DUPLICATE KEY UPDATE` 原子累加，两阶段试算后统一扣减；多租户隔离落地为"检索过滤→强制条件→出口校验→源头只认 JWT"四道防线。
> - 全链路可观测：TraceId 贯穿网关/Feign/MDC/响应体并显式跨线程池传递；Micrometer 自定义指标经 Prometheus + Grafana 可视化，标签仅保留低基数枚举以抑制时序膨胀。

### ✅ 改写后（Agent / AI 应用开发岗版）

> **AIHub 多租户 AI 能力中台 · AI 能力层**
> - 基于 Spring AI 实现模型网关：OpenAI 兼容协议适配多家供应商，按场景选模 + 主备降级；ChatClient 工厂采用 `ConcurrentHashMap` + 双重检查锁 + 60s TTL 缓存。
> - RAG 全链路：PDFBox/POI 解析 → 500 字 100 重叠分片 → Redis Stack 向量检索（topK=4、阈值 0.6、强制租户过滤）；回答携带 `[n]` 引用并落库，支持刷新后溯源；检索 3s 超时自动降级为普通对话。
> - Agent 内核：Planning→Registry 派发→Table/Chart/HtmlDoc/Browser 子 Agent→产物落盘；实现**三重预算**（子任务数/Token/超时）与**服务端可中断**，Token 用 `AtomicLong` 累加，取消走 `ConcurrentHashMap.newKeySet()` 标志位；任务与步骤全落库可回放。
> - MCP 双向能力：作为 Client 接入外部工具（配置即连 + 调用审计）；作为 Server 以一套 `@Tool` 实现同时提供 SSE / stdio / streamable-http 三种传输，供 Claude Desktop、Cursor 调用。
> - 浏览器控制 Agent：不引入 Playwright，用 JDK 自带 WebSocket 直连 CDP 协议操作本机 Chrome，页面标注方案把可交互元素压缩为 `[e3] button 提交`，token 可控且避免模型臆想元素。

### ✅ 改写后（全栈岗版）

> **AIHub 多租户 AI 能力中台 · 前后端**
> - 后端：9 模块微服务（网关 + 平台服务 + AI 服务 + MCP 三模块），Spring Boot 3.5 + Spring AI 1.1.5，REST + 三种流式通道。
> - 管理后台：Vue 3.5 + TypeScript 5.9 + Vite 7 + Element Plus 2.11，Pinia 状态管理；改写 axios 封装以适配后端统一响应体（`code===0` 直接解包返回 `data`，`10002` 跳登录），并实现 token 无感刷新（并发请求队列）；路由采用后端动态菜单（`M/C/F` 三类节点递归转换，按钮不进路由）。
> - 移动端：uni-app + Vue3 编译 H5 与微信小程序双端；**流式渲染双实现**——H5 用 `fetch` + `ReadableStream`（EventSource 无法携带自定义 Header），小程序用 `uni.request({enableChunked:true})` + `onChunkReceived`，并手写半包切分与 UTF-8 解码（小程序无 `TextDecoder`）。
> - 跨端差异用条件编译隔离（4 处：baseUrl、流式实现、产物预览方式）。

## 六、三个岗位的"卖点排序"

同一个项目，卖给不同岗位时**第一卖点必须不同**：

### Java 后端岗
1. **架构约束力**：ArchUnit 把分层写成构建期卡口（大多数人只听过 DDD，没把它变成 CI 门禁）
2. **多租户工程化**：不是"加个 tenant_id 字段"，而是四道防线 + 头部防伪造 + 出口校验
3. **并发与原子性**：配额 upsert、双重检查锁缓存、`AtomicLong` 预算、线程池参数
4. *（次要）* AI 相关——证明你跟得上新技术

### Agent / AI 应用开发岗
1. **Agent 的可控性**：预算 + 中断 + 落库回放（这是 Agent 落地最痛的点，90% 的玩具项目没有）
2. **RAG 工程细节**：分片重叠、引用归属、超时降级、租户过滤、幻觉约束提示词
3. **MCP 双向理解**：既做 Client 又做 Server，三种传输 + 四个真实踩坑
4. **成本意识**：Token 真实统计、四维配额、指标可观测

### 全栈岗
1. **流式全链路贯通**：后端三种通道（SSE / NDJSON / WebSocket）× 前端两种实现（H5 / 小程序）
2. **双端适配能力**：条件编译、小程序限制（不支持 SSE、无 TextDecoder、主包 2MB）
3. **工程化**：Vite 代理、axios 封装、动态路由与权限指令、Dockerfile
4. **能写后端**：不是只会切图，能独立设计接口与表

## 八、练法

1. 把 3 分钟版写成逐字稿，读 3 遍，然后**只留关键词提纲**再讲 3 遍。
2. 录音听自己的"嗯""那个""就是"——**超过 5 次就必须重录**。
3. 让朋友随机打断你提问，练"被打断后 3 秒内接上"的能力。
4. 每个技术点准备一个"**为什么不用 X**"的答案，这是区分度的来源。
