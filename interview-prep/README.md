## 一、这套文档怎么来的

我在动笔前把整个仓库翻了一遍（后端 8 个 Maven 模块 + 两个前端），顺手挖出了一批
**"README/设计文档写了、但代码里其实没有"**的地方。这些地方单独收在
[`12-自测清单与追问地图.md`](12-自测清单与追问地图.md) 的"照妖镜"章节，也包括
[`09-项目难点与STAR故事库.md`](09-项目难点与STAR故事库.md) 里的"别吹过头"清单。

**先说清楚这件事的意义**：面试官一追问就露馅的项目描述，比不写还伤。
宁可自己先知道哪里是虚的，主动降调，也不要被问穿。

## 二、项目一句话定位

> **AIHub 是一个多租户的通用 AI 能力中台**：模型可换、知识可插、工具可注册、Agent 可编排，
> 一切按租户计量与审计。Java 17 + Spring Boot 3.5 + Spring Cloud Alibaba + Spring AI 1.1.5，
> 9 个 Maven 模块，配套 Vue3 管理后台与 uni-app 移动端（H5 + 微信小程序）。

## 五、使用方法（别当小说读）

1. **第一轮（通读）**：按岗位对应顺序读，重点看每个问题下的「**面试官真正想听**」和「**追问预警**」。
2. **第二轮（自测）**：打开 `12`，逐条给自己打勾。凡是"能讲但讲不到代码"的，回原文补。
3. **第三轮（开口）**：对着 `01` 的四版讲法，用手机录音讲一遍，控制在 ±10% 时长内。
4. **第四轮（模拟追问）**：让朋友（或让我）拿 `12` 的追问链随机提问，答不上来的当场标红。
5. **临场**：只看 `11` 的反问清单和 `09` 的三个王牌故事。

## 六、三条铁律

1. **讲不清的代码就别说**。这个项目里模板自带的、没接完的（`ai_event_outbox`、
   ECharts、mock 三文件），都在"照妖镜"里列出来了，主动避开或主动承认。
2. **每个技术选型都要能说"为什么不选另一个"**。
   面试官 80% 的区分度来自 Trade-off，而不是"你用了什么"。
   文档里每个关键决策都给了「为什么不那样做」。
3. **数字要具体**。线程池参数、超时时间、分片大小、相似度阈值、缓存 TTL——
   具体到数字才像自己写的；含糊其辞立刻掉价。文档里所有数字都从代码/配置里抠出来了。
