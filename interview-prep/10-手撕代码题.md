## A. 项目相关题（你真实写过的，务必会写）

### A1 ★ 文本分片（带重叠）—— 最高频的"项目手撕"

**要求**：把长文本切成 size 大小的片段，相邻片段重叠 overlap 个字符。
（我项目里 `TextChunker`：按段落切 → 累积到 size 才 flush → 超长段落走滑动窗口）

```java
public static List<String> split(String text, int size, int overlap) {
    if (size < 100) size = 100;
    if (overlap > size / 2) overlap = size / 2;   // 上限保护
    List<String> out = new ArrayList<>();
    String s = text.trim();
    if (s.isEmpty()) return out;
    int step = size - overlap;                     // 滑动步长
    for (int i = 0; i < s.length(); i += step) {
        out.add(s.substring(i, Math.min(i + size, s.length())));
        if (i + size >= s.length()) break;         // ★ 防止最后一片重复
    }
    return out;
}
```

**面试官会追问的点**：
- **为什么不能让 overlap >= size**？→ 步长 <= 0，**死循环**。所以代码里做了上限保护。
- **最后一片的边界**：`if (i + size >= len) break` 必须有，否则最后会多出一个重复片段。
- **为什么按字符而不是 token**？→ 简单可控，但中文场景下 1 字符 ≈ 0.6~1 token，
  精确控制应该按 **tokenizer** 算（可以用 `jtokkit` 之类）。**答出这一点有深度。**
- **更好的切分**：按段落/标题等**语义边界**切，再对超长段落用滑动窗口。

### A2 ★ 从"脏"模型输出里提取 JSON 数组

**要求**：模型返回 `好的：\n```json\n[{"agent":"html","task":"x"}]\n````，提取数组。

```java
static String extractJsonArray(String raw) {
    if (raw == null) return null;
    int s = raw.indexOf('[');
    int e = raw.lastIndexOf(']');
    if (s < 0 || e <= s) return null;              // 找不到 → 交给降级逻辑
    return raw.substring(s, e + 1);
}
```

**追问**：
- 括号嵌套/字符串里含 `]` 怎么办？→ `lastIndexOf(']')` 在"数组里含字符串 `]`"时会截错。
  更稳的做法是**括号计数扫描**（遇到 `"` 进入字符串态，忽略其中的括号）。
- 更好的方案：**结构化输出**（`response_format: json_object`）或 tool calling 约束，
  从源头避免脏输出。

### A3 ★ 流式半包切分（前后端通用）

```java
// 后端视角：把任意分块的字节流还原成按行事件
StringBuilder buffer = new StringBuilder();
void onChunk(String text) {
    buffer.append(text);
    int idx;
    while ((idx = buffer.indexOf("\n")) >= 0) {
        String line = buffer.substring(0, idx);
        buffer.delete(0, idx + 1);
        if (!line.isBlank()) handle(line);         // 交给 JSON 解析
    }
    // 残留的半行留在 buffer，等下一块
}
```

**要点**：**永远不要把最后一段不完整的行丢掉或强行 parse**。

### A4 ★ 双重检查锁缓存（含 TTL）

```java
static class Entry { final Object val; final long expireAt;
    boolean expired(){ return System.currentTimeMillis() > expireAt; } }

final Map<String, Entry> cache = new ConcurrentHashMap<>();   // CHM 提供可见性保证

Object get(String key, Supplier<Object> loader, long ttlMs) {
    Entry e = cache.get(key);
    if (e == null || e.expired()) {
        synchronized (cache) {
            e = cache.get(key);                    // ★ 二次检查
            if (e == null || e.expired()) {
                e = new Entry(loader.get(), System.currentTimeMillis() + ttlMs);
                cache.put(key, e);
            }
        }
    }
    return e.val;
}
```

**必答**：为什么不需要 `volatile`？→ 因为 `ConcurrentHashMap` 的 `get/put`
自带 happens-before 语义，**能看见完整的构造结果**。

### A5 ★ 令牌桶限流（简化版）

```java
class TokenBucket {
    private final double rate;      // 每秒生成令牌数
    private final int capacity;
    private double tokens;
    private long lastRefill;

    TokenBucket(double rate, int capacity) {
        this.rate = rate; this.capacity = capacity;
        this.tokens = capacity; this.lastRefill = System.nanoTime();
    }

    synchronized boolean tryAcquire(int n) {         // 单JVM用synchronized即可
        refill();
        if (tokens >= n) { tokens -= n; return true; }
        return false;
    }

    private void refill() {
        long now = System.nanoTime();
        double add = (now - lastRefill) / 1e9 * rate;
        tokens = Math.min(capacity, tokens + add);
        lastRefill = now;
    }
}
```

**追问**：
- 分布式怎么做？→ Redis + Lua（原子地"计算令牌 + 扣减"）。
- 令牌桶 vs 漏桶？→ **令牌桶允许突发**（攒的令牌一次用完），漏桶**恒定速率**输出。

## B. 常考经典题

### B1 LRU 缓存（两种写法都要会）

**写法一：`LinkedHashMap`（最快）**

```java
class Lru<K,V> extends LinkedHashMap<K,V> {
    private final int cap;
    Lru(int cap){ super(cap, 0.75f, true); this.cap = cap; }  // ★ accessOrder=true
    @Override protected boolean removeEldestEntry(Map.Entry<K,V> e){ return size() > cap; }
}
```

**写法二：HashMap + 双向链表（面试官更想看这个）**

```java
class Lru2 {
    class Node { int k, v; Node pre, next; }
    private final Map<Integer, Node> map = new HashMap<>();
    private final Node head = new Node(), tail = new Node();  // 哨兵，省去 null 判断
    private final int cap;

    Lru2(int cap){ this.cap = cap; head.next = tail; tail.pre = head; }

    int get(int k){
        Node n = map.get(k);
        if (n == null) return -1;
        moveToHead(n);                    // 访问后移到头（最近使用）
        return n.v;
    }
    void put(int k, int v){
        Node n = map.get(k);
        if (n != null) { n.v = v; moveToHead(n); return; }
        n = new Node(); n.k = k; n.v = v;
        map.put(k, n); addAfterHead(n);
        if (map.size() > cap) { Node old = tail.pre; remove(old); map.remove(old.k); }
    }
    private void addAfterHead(Node n){ n.pre = head; n.next = head.next;
        head.next.pre = n; head.next = n; }
    private void remove(Node n){ n.pre.next = n.next; n.next.pre = n.pre; }
    private void moveToHead(Node n){ remove(n); addAfterHead(n); }
}
```

**考点**：`get` 时间复杂度 O(1)、**为什么用双向链表**（删除任意节点需要前驱指针）、哨兵节点简化边界。

### B2 生产者-消费者（三种写法）

```java
// 推荐：BlockingQueue（也是线程池的实现基础）
BlockingQueue<Task> q = new ArrayBlockingQueue<>(1000);

// 手写版（wait/notify）——注意必须用 while 而不是 if
synchronized (lock) {
    while (q.size() == CAP) lock.wait();   // ★ while 防止虚假唤醒
    q.add(task); lock.notifyAll();
}
```
**必答**：**为什么用 `while` 不用 `if`**？→ 线程可能被**虚假唤醒**（spurious wakeup），
唤醒后条件可能又变了，必须重新检查。

### B3 单例（三种，DCL 必须写对）

```java
// 1. 枚举（最推荐，天然防反射与序列化破坏）
enum Singleton { INSTANCE; }

// 2. 静态内部类（懒加载 + 无锁，利用类加载线程安全）
class Holder { private Holder(){} private static class Inner {
    static final Holder I = new Holder(); } static Holder get(){ return Inner.I; } }

// 3. DCL（考点：volatile 必须加）
class Dcl { private static volatile Dcl i;
    static Dcl get(){ if (i == null) synchronized (Dcl.class) {
        if (i == null) i = new Dcl(); } return i; } }
```
**必答**：`volatile` 的作用是**禁止指令重排**——
`new Dcl()` 会拆成"分配内存 → 初始化 → 赋值引用"，
若重排成"分配 → 赋值 → 初始化"，另一个线程可能拿到**未初始化完成的对象**。

### B4 其它高频（知道思路 + 关键代码）

| 题 | 关键点 |
| --- | --- |
| **TopK** | 小顶堆（PriorityQueue，容量 K），遍历时比堆顶大就替换。O(n log K) |
| **二分查找** | 边界写法统一用 `[left, right)` 左闭右开；`mid = left + (right-left)/2` 防溢出 |
| **反转链表** | 三指针 `pre/cur/next` 迭代；递归版要能讲清 |
| **快排** | partition 的双指针写法；**最坏 O(n²)**（有序数组取首元素为 pivot），优化：随机 pivot / 三数取中 |
| **两栈实现队列** | 入栈 push，出栈 pop；**出栈空时才把入栈全部倒过来**（摊还 O(1)） |
| **大数相加** | 字符串从尾往前逐位加 + 进位；或用 `BigInteger` |
| **死锁示例** | 两个线程以相反顺序获取两把锁 → 用 `jstack` 能看到 `Found one Java-level deadlock` |

## C. 手撕时的行为准则（很影响评分）

1. **先复述需求 + 确认边界**：空输入？参数非法？并发？——**这两分钟比代码值钱**。
2. **先说思路再写代码**："我打算用 XX 结构，复杂度是 O(n log k)，因为……"
3. **边写边说**：不要沉默十分钟。沉默会让面试官觉得卡住了。
4. **主动说复杂度和边界**：写完后自己 review 一遍空值、越界、并发。
5. **写不出就请求提示**：*"我可以先用 O(n²) 的写法，然后再优化吗？"*
   ——这比干坐着强一百倍，而且大多数面试官会同意。
6. **Java 岗特别注意**：写并发题时**主动说明"这个场景在多线程下有什么问题"**，
   即使题目没要求并发安全。
