# 11 · 面试策略与反问

> 技术决定下限，**表达和策略决定上限**。
> 同样一个项目，讲得好是"有架构思维的工程师"，讲不好是"跟着教程做了一遍"。

---

## 一、面试各轮的重点

| 轮次 | 面试官 | 考察重点 | 你的策略 |
| --- | --- | --- | --- |
| **一面（技术）** | 同级/高级工程师 | 基础扎实度 + 项目真实性 | 项目要能讲到代码级；八股要能落到自己的实现上 |
| **二面（技术深挖）** | 技术 Leader | 设计能力 + 权衡意识 + 深度 | 主动讲 Trade-off 和你"没做成"的部分 |
| **三面（交叉/架构）** | 架构师 / 总监 | 系统性、前瞻性、技术判断 | 讲演进路径（一期/二期/三期）和"如果重做" |
| **HR 面** | HR | 稳定性、动机、薪资、软素质 | 真实、稳定、有成长诉求，不要抱怨上家 |

## 二、自我介绍（1 分钟模板）

> 面试官您好，我是 XX，有 X 年 Java 后端 / 全栈开发经验。
>
> 最近一年我主要在做一个多租户的 AI 能力中台项目（AIHub），
> 技术栈是 Java 17 + Spring Boot 3.5 + Spring Cloud Alibaba + Spring AI，
> 我负责了其中 **AI 服务的能力层**和**多租户/配额体系**的设计与实现
> （或：负责了前后端整体，包括流式通道的双端实现）。
>
> 这个项目里我比较有把握的三块是：**Agent 的预算控制与可中断**、**RAG 的引用溯源**、
> 以及**多租户隔离与配额的工程化**。
>
> 很高兴来面试，请多指教。

**要点**：不要复述简历；**用一句话定位自己 + 给面试官三个可选的深挖入口**。

## 三、反问清单（★ 这是最容易加分也最容易浪费的环节）

**原则**：反问要体现你**关心的是"能不能做好这件事"**，而不是"待遇如何"（那是 HR 面的事）。

### 对技术面试官（一面/二面）

1. 这个岗位所在团队目前**最棘手的技术问题**是什么？
2. 如果我入职，**前三个月**最可能负责哪块？
3. 你们现在的 AI 相关能力是自建还是接第三方？**遇到过哪些坑**？
4. 团队的**代码审查和架构卡口**是怎么做的？（引出 ArchUnit 的话题，你可以顺势讲你的实践）
5. 服务的**可观测体系**是怎么建的？有没有做过指标/链路的治理？
6. 技术选型上，团队更倾向**稳定成熟**还是**积极跟进新版本**？

### 对 Leader（三面）

1. 团队未来半年到一年的**技术规划**是什么？
2. 这个岗位**期望解决的核心问题**是什么？（说明你是来解决问题的）
3. 团队的**协作节奏**：需求怎么来？发版周期？线上问题怎么响应？
4. 您觉得在这个团队做得好的人，有什么**共同特质**？

### 对 HR

1. 薪资结构（**base / 绩效 / 年终 / 股票**）、发薪月数；
2. 试用期时长与转正标准；
3. 加班与调休制度、值班安排；
4. 五险一金基数与比例。

**❌ 不要问的**：
- "你们加班多吗？"（可以换个说法："团队平时的迭代节奏是怎样的？"）
- "我今天表现怎么样？"（把评价权交给对方，且显得不自信）
- 网上能查到的公司基本信息。

## 四、薪资谈判

**原则**：
1. **不先报价**（"我更想先了解这个岗位的薪酬范围"）；
2. 如果必须报，**给区间上沿**，并说明依据（当前薪资 + 市场行情 + 期望涨幅 20~30%）；
3. **手里有多个 offer 是最强的筹码**（不要撒谎，但可以说"目前还在面几家"）；
4. **谈 total package**，不要只盯 base（年终、股票、公积金基数可能差很多）；
5. **不要立刻答应**，要"回去考虑一下"，给对方留出审批时间。

## 五、行为面（BQ）常见问题与答法

| 问题 | 答法框架 | 你的素材 |
| --- | --- | --- |
| **最有成就感的事** | STAR | 见 [09](09-项目难点与STAR故事库.md) 故事 1 或 8 |
| **最大的失败/踩过的坑** | 承认 + 归因 + 改进 + 沉淀 | 故事 2（MinIO 白排查五轮）**特别好**——诚实、有方法论沉淀 |
| **和同事意见冲突** | 先共情 → 讲事实与数据 → 达成共识或保留意见 | 可以讲"是否引入 MQ"、"是否拆分 AI 服务"这类技术决策讨论 |
| **怎么学习新技术** | 官方优先 → 动手做 → 输出（文档/博客/代码） | "我学 Spring AI 时先读官方文档和样例，然后在项目里把 MCP 三种传输都跑通，最后把踩坑写成 README 的小节" |
| **职业规划** | 1 年深耕 + 3 年方向，和岗位对齐 | "1 年内把 AI 应用工程化的能力做深；3 年能独立负责一条业务线的技术架构" |
| **为什么离职** | **绝不抱怨上家**，讲"想要什么" | "希望做更有挑战、技术密度更高的方向" |
| **你的缺点** | 真实的、可改善的、不影响岗位的 | "我有时候会过度追求方案的完备性，后来学会了用里程碑拆分期——先落地再优化" |

## 六、★ 怎么讲"这是课程项目 / 自学项目"

**这是你最大的心理包袱，但其实很容易化解。**

**不要说**："这是个跟着课程做的项目。"
**要说**：

> "这个项目的技术选型参考了课程内容——**这让我少走了很多选型的弯路**。
> 但课程内容只到'功能实现'这一层，我在它之上补的是**工程化的部分**：
>
> 1. **架构约束力**：用 ArchUnit 把分层做成构建期卡口，这是课程里没有的；
> 2. **可控性**：Agent 的三重预算、服务端可中断、步骤落库回放——
>    这些是 Agent 能不能上生产的关键，玩具项目基本都不做；
> 3. **多租户与配额**：四道防线 + 原子扣减 + 四维计量；
> 4. **可观测**：TraceId 全链路 + Prometheus/Grafana 仪表板。
>
> 简单说：**课程给我的是骨架，工程化的部分是我自己设计的。**

**这段话的厉害之处**：它没有否认参考课程（诚实），
但把"我做了什么"精确地界定在**最有价值的那一层**上。

## 七、致命失误清单

| ❌ 失误 | 后果 | ✅ 正确做法 |
| --- | --- | --- |
| **简历上写了不会的技术** | 一问就崩，且被判定为不诚信 | 只写能讲到代码级的；"了解"和"熟悉"要分清 |
| **被追问时硬编** | 编的答案前后矛盾，直接出局 | "这个点我没有深入研究过，我的理解是……如果是我来解决，我会先……" |
| **说"这个很简单"** | 显得浅薄 | 改说"这个我当时是这么做的……" |
| **贬低前公司/前同事** | 红旗 | 客观描述，聚焦事实 |
| **沉默超过 1 分钟不说话** | 面试官无法判断你在思考还是卡住 | 边想边说："我在想这个场景的边界……" |
| **反问环节问待遇** | 显得只关心钱 | 技术问题留给技术面，待遇留给 HR |
| **项目讲太长（>5 分钟）** | 面试官失去耐心，追问点被稀释 | 3 分钟版 + 留钩子 |

## 八、面试当天的执行清单

**面试前 30 分钟**：
- [ ] 过一遍 `01` 的 3 分钟讲法（**提纲版**）；
- [ ] 过一遍 `09` 的三个王牌故事（stdio 污染 / MinIO 包名 / 半包 UTF-8）；
- [ ] 过一遍 `12` 的 20 题速答（只看自己标红的部分）；
- [ ] 检查环境（网络、IDE、摄像头、纸笔）。

**面试中**：
- [ ] 每个技术点讲完**停顿一秒**，给面试官追问的空间；
- [ ] 被问到不会的：**先说已知，再说思路，最后承认边界**；
- [ ] **记下**面试官反复追问的方向（那是岗位真实需求）。

**面试后 24 小时内**：
- [ ] 复盘：把答不上来的题记到 `12` 的"待补"区；
- [ ] 给 HR/面试官发一封简短的感谢邮件（**提一个面试中具体的讨论点**，显得认真）；
- [ ] 如果挂了，**诚恳请求反馈**（"能请您指出我最需要补强的一两点吗？"——很多面试官会给）。

## 九、三个"万能收尾句"

1. **被问到边界时**：
   "这块我目前的理解到这个程度，**如果要做到生产级，我还会补 X 和 Y**。"
2. **被问到没做过的场景**：
   "我没在生产上做过，但**类似的思路我在 XX 场景用过**——先…再…，主要风险是…"
3. **面试官指出你的问题时**（非常关键）：
   "您说得对，这确实是我没考虑到的。**您的方案是……？**"
   ——**接受指正 + 请教**，比辩解加十分。
