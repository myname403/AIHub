## 2. ADR：关键技术决策记录

### ADR-1 为什么选 Spring AI 1.1.x 而不是 2.0

| 维度 | Spring AI 1.1.x + Boot 3.5 | Spring AI 2.0 + Boot 4 |
| --- | --- | --- |
| JDK | 17 ✅ | 17 最低（21 推荐） |
| 与课程文档一致性 | **完全一致**（教材即 1.x 时代） | 差异大（全 builder 化、Jackson 3 包名迁移） |
| MCP 支持 | 独立 starter，功能完整 | 合入核心 |
| 支持周期 | Boot 3.5 已 EOL（2026-06-30 后无官方补丁） | 在支持周期内 |
| 学习成本 | 低 | 中高 |

**决策**：选 **1.1.x**。理由是本项目的首要目标是**把课程知识工程化落地**，与教材同版本可最大化复用、最小化踩坑。Boot 3.5 EOL 的风险通过学习项目场景可接受。

**缓解措施**：所有 Spring AI 调用收敛在 `aihub-infra-ai` 内部，业务层只依赖 `aihub-domain` 的自有接口。未来升 2.0 时改动范围被限制在适配层。

### ADR-2 为什么用 Redis Stack 做向量库

| 候选 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **Redis Stack** | 项目本就要用 Redis；部署组件少；Spring AI 原生支持；元数据过滤完善 | 向量常驻内存；规模有限；维度建索引后不可改 | ✅ **一期选用** |
| PGVector | 关系库一体化、持久化好 | 多引入 PG；与 MySQL 并存 | 备选 |
| Elasticsearch | 中文分词与混合检索最强 | 组件重、运维成本高 | 备选 |
| Milvus | 专业向量库、规模大 | 部署最重 | 后期 |

**决策**：一期用 Redis Stack，通过 `VectorStoreProvider` 抽象隔离。当分片量超过百万级或需要复杂全文检索时，切换成本被限制在单个实现类内。

### ADR-3 为什么 MCP 拆成 service / sse / stdio 三模块

直接采用课程第三章的工程结构：

- `aihub-mcp-service`：工具的**业务实现**，与协议无关，可单测
- `aihub-mcp-sse`：以 SSE 对外提供在线服务（主流方式）
- `aihub-mcp-stdio`：打成 jar，供 `java -jar` 进程调用（本地集成方式）

收益：一套工具实现，两种协议复用；与课程一致，便于对照学习。

### ADR-4 为什么流式要三通道并存

微信小程序**不支持原生 SSE**，必须走 `enableChunked` 分块传输；而 Agent 长任务需要双向通信（可中断），SSE 做不到。因此：

| 场景 | 通道 |
| --- | --- |
| H5 对话 | SSE |
| 小程序对话 | NDJSON Chunked |
| Agent 长任务（全端） | WebSocket |

三者共用同一套 `StreamEvent` 信封与 `StreamSink` 抽象，业务层无需区分。

## 3. 后端核心依赖

### 3.1 BOM 与仓库

```xml
<properties>
    <spring-ai.version>1.1.x</spring-ai.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-bom</artifactId>
            <version>${spring-ai.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

> 若 Maven Central 解析不到对应版本，补加 Spring Milestones / Snapshots 仓库。

## 4. 前端选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | uniapp + Vue 3 | 一套代码编译到 H5 / 微信小程序 / App |
| 语言 | TypeScript | 事件帧与接口模型较多，类型保障收益大 |
| 状态 | Pinia | Vue 3 官方推荐 |
| UI | uni-ui | 官方组件库，多端兼容 |
| Markdown 渲染 | Towxml 或自研渲染 | 小程序不支持 `v-html`，不能用常规 Markdown 组件 |
| 分包 | 管理端页面放分包 | 小程序主包 2MB 限制 |

**多端适配要点**
- 流式：条件编译区分 SSE 与 chunked 实现，对外统一 `onEvent` 回调
- 样式：统一使用 rpx
- 平台差异：用 `// #ifdef MP-WEIXIN` 等条件编译隔离

## 5. 升级与迁移路径

| 触发条件 | 动作 |
| --- | --- |
| 需要 Spring AI 2.0 特性 | 改造 `aihub-infra-ai` 适配层：模型选项改 builder、Jackson 3 包名替换、MCP 依赖合入核心；`aihub-domain` 与 `aihub-application` 不动 |
| 向量规模超百万 | 新增 `PgVectorStoreProvider` 或 `ElasticsearchProvider` 实现，切换配置项 |
| 需要多实例强一致 | 引入分布式锁与 MQ（替换 `DomainEventPublisher` 实现，配合 outbox 表） |
| 需要原生 App | uniapp 直接编译到 App 端，业务代码基本复用 |
