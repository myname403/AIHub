# 05 · 数据库设计说明书

---

## 1. 设计规范

| 项 | 规范 |
| --- | --- |
| 字符集 | `utf8mb4` / `utf8mb4_0900_ai_ci` |
| 命名 | 小写 + 下划线；按域加前缀（`sys_` 身份域、`ai_` AI 能力域） |
| 主键 | `BIGINT` 雪花 ID（或自增），统一字段名 `id` |
| 通用字段 | 业务表必带 `tenant_id`；审计字段 `create_by / create_time / update_by / update_time`；逻辑删除 `deleted` |
| 租户 | **所有业务表第一索引位为 `tenant_id`**，复合索引以 `tenant_id` 开头 |
| 迁移 | 全部 DDL 由 **Flyway** 管理，禁止手工改库 |
| 向量索引 | 不由 Flyway 管理，由 `VectorStoreProvider` 在应用启动时显式创建/校验 |

## 3. 核心表 DDL 示例

```sql
CREATE TABLE sys_tenant (
  id            BIGINT PRIMARY KEY,
  name          VARCHAR(64)  NOT NULL,
  code          VARCHAR(64)  NOT NULL UNIQUE,
  status        TINYINT      NOT NULL DEFAULT 1,
  expire_at     DATETIME     NULL,
  create_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE ai_app (
  id             BIGINT PRIMARY KEY,
  tenant_id      BIGINT       NOT NULL,
  name           VARCHAR(128) NOT NULL,
  system_prompt  TEXT         NULL,
  model_route_id BIGINT       NULL,
  agent_strategy VARCHAR(32)  NOT NULL DEFAULT 'none',   -- none / react / plan_execute
  memory_policy  VARCHAR(32)  NOT NULL DEFAULT 'window',
  temperature    DECIMAL(3,2) NOT NULL DEFAULT 0.70,
  status         TINYINT      NOT NULL DEFAULT 1,
  create_time    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_tenant (tenant_id),
  KEY idx_tenant_status (tenant_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE ai_knowledge_base (
  id                 BIGINT PRIMARY KEY,
  tenant_id          BIGINT       NOT NULL,
  name               VARCHAR(128) NOT NULL,
  embedding_model_id BIGINT       NOT NULL,
  vector_dim         INT          NOT NULL,     -- 必须与模型维度一致，强校验
  index_name         VARCHAR(128) NOT NULL,     -- Redis 索引名（带 v{n} 版本）
  status             TINYINT      NOT NULL DEFAULT 1,
  create_time        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_tenant (tenant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE ai_document_chunk (
  id             BIGINT PRIMARY KEY,
  tenant_id      BIGINT   NOT NULL,
  kb_id          BIGINT   NOT NULL,
  doc_id         BIGINT   NOT NULL,
  seq            INT      NOT NULL,
  content        MEDIUMTEXT NOT NULL,
  token_count    INT      NULL,
  vector_status  TINYINT  NOT NULL DEFAULT 0,   -- 0待向量化 1已入库 2失败
  metadata_json  JSON     NULL,
  create_time    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_tenant_kb (tenant_id, kb_id),
  KEY idx_doc (doc_id, seq)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE ai_message (
  id              BIGINT PRIMARY KEY,
  tenant_id       BIGINT   NOT NULL,
  conversation_id BIGINT   NOT NULL,
  role            VARCHAR(16) NOT NULL,          -- user / assistant / tool
  content         MEDIUMTEXT  NULL,
  token_in        INT      NULL,
  token_out       INT      NULL,
  model_code      VARCHAR(64) NULL,
  cost_ms         INT      NULL,
  status          TINYINT  NOT NULL DEFAULT 1,
  create_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_tenant_conv (tenant_id, conversation_id),
  KEY idx_tenant_time (tenant_id, create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 4. Redis Key 规范

统一前缀 `aihub:`，租户维度置于第二层，便于按租户统计与清理。

| Key 模式 | 类型 | 用途 | 示例 |
| --- | --- | --- | --- |
| `aihub:{tenant}:quota:{dimension}:{periodKey}` | String（计数） | 配额计数 | `aihub:1001:quota:token:2026-09` |
| `aihub:{tenant}:memory:{conversationId}` | List | 会话记忆缓存 | `aihub:1001:memory:556` |
| `aihub:{tenant}:agent:ckpt:{taskId}` | Hash | Agent 检查点 | `aihub:1001:agent:ckpt:77` |
| `aihub:lock:ingest:{docId}` | String（NX） | 入库任务去重锁 | `aihub:lock:ingest:3210` |
| `aihub:app:spec:{appId}` | Hash | 应用配置缓存 | `aihub:app:spec:12` |

**向量数据**：使用 Spring AI `RedisVectorStore`，Key 前缀默认 `embedding:`，索引名由 `ai_knowledge_base.index_name` 指定。

## 5. ★ 向量索引与租户隔离

### 5.1 Redis 索引结构

```
FT.CREATE idx:kb:{kbId}:v1
  ON JSON
  PREFIX 1 embedding:
  SCHEMA
    $.tenant_id  AS tenant_id  TAG
    $.kb_id      AS kb_id      TAG
    $.doc_id     AS doc_id     TAG
    $.content    AS content    TEXT
    $.embedding  AS embedding  VECTOR HNSW 6
                 TYPE FLOAT32 DIM {vector_dim} DISTANCE_METRIC COSINE
```

**约束**：
- `DIM` 建索引后**不可修改**，更换 Embedding 模型必须重建索引
- 混合过滤（TAG 过滤 + KNN）过滤过严时可能召回不足，需监控空结果率
- 向量常驻内存，需评估容量

### 5.2 隔离方案

| 方案 | 适用 | 做法 |
| --- | --- | --- |
| **共享索引 + TAG 过滤**（默认） | 大多数租户 | 所有检索强制追加 `@tenant_id:{xxx}` |
| **专属索引** | 大租户 / 合规要求 | 每租户独立索引，`VectorStoreProvider` 按租户路由 |

### 5.3 四道防线（与 03 号文档一致）

1. 业务禁止注入 `VectorStore`，唯一入口 `KnowledgeRetriever`
2. Provider 内部**强制 AND 注入 `tenant_id`**
3. 返回后 `TenantGuard` 逐条校验 metadata 租户，不匹配丢弃并告警
4. `tenantId` 只从 JWT / API Key 解析，绝不接受前端传参；MyBatis 拦截器兜底

### 5.4 零停机重建索引

索引名带版本号 `v{n}` + Redis 索引别名（`FT.ALIASADD` / `FT.ALIASUPDATE`）。
换 Embedding 模型流程：**建 v2 → 双写 → 回灌历史分片 → 切别名 → 删除 v1**。

## 6. Flyway 迁移规范

- 文件命名：`V{版本号}__{简述}.sql`，如 `V1__init_schema.sql`
- 版本号全局递增，禁止修改已上线的迁移文件
- 每张表一个变更一个版本，便于回滚定位
- **向量索引不属于 Flyway 管理范围**，由应用启动时校验并创建
- 初始化数据（如内置示例模板、供应商定义）放在 `V{n}__init_data.sql`
