## 1. 这个项目是什么？

**AIHub**：一个多租户 SaaS 化的 AI 能力平台。租户（公司）注册后可以：
- 配置自己的 AI 应用（助手）：选模型、写系统提示词、绑定知识库；
- 与 AI 对话（支持流式输出、RAG 知识库问答、Agent 自动化任务）；
- 管理开放 API Key 供自己的系统集成；
- 查看用量与配额（token 消耗、调用次数）。

**技术栈一览**（每个组件在对应模块文档里都有专章讲解）：

| 层 | 技术 | 版本 |
|---|---|---|
| 语言 | Java | 17（record、switch 表达式、text block 等新语法都有实战） |
| 框架 | Spring Boot | 3.5.0 |
| 微服务 | Spring Cloud + Spring Cloud Alibaba | 2025.0.0 |
| 注册/配置中心 | Nacos | 3.0.3 |
| 限流熔断 | Sentinel | 规则持久化到 Nacos |
| AI | Spring AI | 1.1.5 |
| ORM | MyBatis-Plus | 3.5.7（+Flyway 数据库迁移） |
| 存储 | MySQL 8 双库 + Redis Stack（向量库）+ MinIO（可选） | |
| 安全 | JWT (jjwt) + API Key (HMAC) + AES-GCM 加密 | |
| 可观测 | Micrometer + Prometheus + Grafana + TraceId 链路追踪 | |

## 2. 全局架构图（先建立空间感）

```
                              ┌─────────────────────────────┐
   前端(uni-app H5/小程序) ──→ │   aihub-gateway :8080       │
   第三方系统(X-API-Key)  ──→ │  路由·鉴权·限流·TraceId      │
                              └──────┬───────────────┬──────┘
                    /auth/**,/api/platform/**    /api/ai/**
                                     ↓               ↓
                    ┌────────────────────────┐  ┌──────────────────────────┐
                    │ aihub-platform :8081   │←─│ aihub-ai :8082           │
                    │ 登录/租户/用户/APIKey   │  │ 对话/RAG/Agent/模型网关   │
                    │ 配额扣减/用量看板       │Feign│ Spring AI / Redis 向量  │
                    └───────────┬────────────┘  └──────────┬───────────────┘
                                │       aihub-api 契约      │
                    ┌───────────┴──────────────┬───────────┴──────────┐
                    │ MySQL aihub_platform     │ MySQL aihub_ai       │
                    │ sys_* / 配额 / 用量       │ 会话/知识库/Agent/模型 │
                    └──────────────────────────┴──────────────────────┘
   外部依赖：Nacos(注册+配置) · Sentinel(限流) · DeepSeek 等模型 API · Redis Stack · MinIO

   另有 MCP 三件套：aihub-mcp-service(工具) + mcp-sse(9001) + mcp-stdio(CLI)
   → 让 Claude Desktop / IDE 等外部 AI 客户端调用 AIHub 的知识库与对话能力
```

**三条铁律（贯穿所有代码的安全/架构约束）**：
1. **租户隔离**：租户 ID 只能从 JWT/API Key 解析（网关写入 X-Tenant-Id 头），绝不接受前端传参；所有查询带 tenant_id；
2. **数据自治**：每个服务独占自己的库，服务间只能走接口（禁止跨库 JOIN）；
3. **边界统一鉴权**：鉴权只在网关做一次，下游信任网关写的头（网关负责剥离伪造头）。

## 3. 学习路线图（建议顺序）

```
第 1 步  环境搭建：docker-compose 起中间件（见第 4 节）→ 编译运行（见第 5 节）
第 2 步  aihub-common    ← 所有代码的地基：统一响应/异常/租户/追踪（文档 01）
第 3 步  aihub-api       ← 理解"服务间怎么互相调用"（文档 02）
第 4 步  aihub-gateway   ← 一个请求怎么进系统：路由/鉴权/限流（文档 03）
第 5 步  platform        ← 登录/JWT/配额，最标准的分层写法（文档 04）
第 6 步  ai-service      ← 最难最核心：DDD/Spring AI/RAG/Agent（文档 05）
第 7 步  mcp 三件套       ← 开阔视野：把能力开放给外部 AI（文档 06）
```

**每一步的学习方法**：
1. 先读对应的学习文档（建立框架）；
2. 再对照源码读（文档里都标了类名）——重点看方法内部步骤注释；
3. 最后跑通"学习自测题"（每份文档末尾），答不上来回去重读。

**动手实验建议**（比读十遍代码更有效）：
- 在 `R.ok()` 里加一行日志，观察每次请求的 traceId 是否一致；
- 故意把网关 jwt-secret 改掉，看登录后会发生什么（401）；
- 用 Swagger（http://localhost:8081/swagger-ui.html）直连调接口，体会"必须带 X-Tenant-Id 头"；
- 跑 `ArchitectureTest`，然后在 web 层 import 一个 infra 类，看测试怎么变红；
- 删掉 AuthGlobalFilter 里"先 remove 再 set 头"的 remove，用 curl 伪造 X-Tenant-Id 头，理解这个安全设计。

## 4. 环境搭建

**前置**：JDK 17、Maven 3.8+、Docker（含 docker compose）、（可选）Node 16+ 跑前端。

```bash
# ① 起中间件（MySQL 双库自动初始化 + Redis Stack + Nacos + Sentinel）
cd aihub
docker compose up -d
# MySQL: 3306（root/aihub123，库名 aihub_platform / aihub_ai）
# Redis Stack: 6379（含 search 模块，向量库必须用它，普通 Redis 不行）
# Nacos 控制台: http://localhost:8848 （nacos/nacos）
# Sentinel 控制台: http://localhost:8858

# ② 后端编译运行（三个服务三个终端，或 IDE 里分别启动）
mvn clean install -DskipTests
mvn -pl aihub-gateway spring-boot:run
mvn -pl aihub-platform-service spring-boot:run
mvn -pl aihub-ai-service spring-boot:run
```

**启动顺序**：中间件 → platform/ai（可并行）→ gateway。验证：Nacos 控制台"服务列表"里能看到 3 个服务。

## 6. 零基础概念地图（遇到陌生词先查这里）

| 术语 | 一句话解释 | 详见 |
|---|---|---|
| 微服务 | 把一个大系统拆成多个独立部署的小服务，各自有数据库，通过接口协作 | 本文第 2 节 |
| 网关 | 系统唯一入口：路由、鉴权、限流 | 03 |
| Nacos | 注册中心（服务互相找到对方）+ 配置中心（改配置不重启） | 03 |
| Feign | 声明式 HTTP 客户端：写接口=发请求 | 02 |
| JWT | 自带签名的令牌，验签即认人，无状态 | 01/04 |
| 多租户 | 一套系统服务多家公司，数据按 tenant_id 隔离 | 01/04 |
| ThreadLocal | 线程私有储物柜；用完必须清理 | 01 |
| SSE / NDJSON / WebSocket | 三种服务端推送技术（本项目三种流式通道） | 05 |
| RAG | 先检索知识库再回答（开卷考试），防幻觉 | 05 |
| Agent | 能自主拆解任务、调用工具的 AI 程序 | 05 |
| function calling | 模型决定"调用哪个函数"并由框架执行 | 05 |
| MCP | AI 应用调用外部工具的开放协议 | 06 |
| DDD | 领域驱动设计；本项目用其分层思想（web/application/domain/infra） | 05 |
| ArchUnit | 把架构规则写成测试，违反即构建失败 | 05 |
| 雪花 ID | 分布式唯一 ID（时间戳+机器号+序列），代替数据库自增 | 04 |
| 幂等 | 同一操作执行多次结果不变（用 requestId 去重） | 02 |
| fail-fast / fail-closed | 出错立即拒绝；鉴权场景"不确定就拒绝" | 01/03 |
| 降级放行 | 依赖故障时不拒绝请求（配额/统计类），保可用性 | 05 |

## 7. 通读代码时的通用规范（全项目适用）

1. **分层**：Controller（三行式）→ Service（业务）→ Mapper（数据）；AI 服务是 DDD 四层；
2. **命名**：接口 I 前缀不用；DO 后缀=表映射；SPI=领域接口；Impl 或 Db*/Redis* 前缀=实现；
3. **返回**：Controller 一律返回 `R<T>`；错误一律 `throw new BizException`；
4. **注入**：构造器注入（@RequiredArgsConstructor），不用字段 @Autowired；
5. **配置**：`${ENV:default}` 环境变量优先；可热调参数用 @ConfigurationProperties；密钥用 @Value 且不落库不打日志；
6. **日志**：占位符 `{}`，不用字符串拼接；异常对象作最后一个参数打堆栈；
7. **注释**：类头说职责与位置，方法说参数/返回/异常，复杂逻辑写"为什么"而不是"是什么"。
