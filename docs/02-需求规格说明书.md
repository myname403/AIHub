# 02 · 需求规格说明书

> 编号规则：`FR-x` 功能需求，`NFR-x` 非功能需求，`AC` 验收标准。
> 优先级：**P0** 一期必须 ｜ **P1** 二期 ｜ **P2** 后续。

---

## 1. 功能需求

### FR-1 租户与身份（P0）

| 用户故事 | 作为**平台管理员**，我要创建租户并分配资源配额，以便隔离不同客户 |
|---|---|
| AC-1.1 | 可创建 / 停用租户，租户拥有独立的数据空间 |
| AC-1.2 | 租户下的用户必须属于唯一租户，登录令牌携带 `tenantId` |
| AC-1.3 | 支持角色：平台管理员 / 租户管理员 / 应用配置者 / 终端用户 |
| AC-1.4 | 支持 API Key 接入，Key 绑定租户与应用，可吊销、可设过期 |
| AC-1.5 | **跨租户访问必须被拒绝**，且有自动化测试用例覆盖 |

### FR-2 应用（助手）管理（P0）

| 用户故事 | 作为**应用配置者**，我要通过配置组合出一个 AI 应用，而无需改代码 |
|---|---|
| AC-2.1 | 应用配置包含：名称、系统提示词、模型（含场景路由）、知识库、工具集、Agent 策略、记忆策略、温度等参数 |
| AC-2.2 | 配置保存后即时生效，无需重启 |
| AC-2.3 | 支持应用的启用 / 停用、复制（从模板创建） |
| AC-2.4 | **内置「教育助手」示例模板**：含演示知识库、四技能提示词、`queryCourseById` / `prePlaceOrder` 工具示例，可一键复制 |

### FR-3 模型管理（P0）

| 用户故事 | 作为**租户管理员**，我要配置多个模型并在它们之间切换，以便平衡成本与效果 |
|---|---|
| AC-3.1 | 支持供应商：OpenAI 兼容、**火山方舟 DeepSeek**、**通义 DashScope**、本地 Ollama |
| AC-3.2 | 密钥加密存储，日志与接口返回值中永不出现明文密钥 |
| AC-3.3 | 支持按场景选模：聊天 / 检索 / 嵌入 / Agent 规划 可配不同模型 |
| AC-3.4 | 主模型失败时自动降级到备用模型，降级事件记入审计日志 |
| AC-3.5 | 新增一家供应商只需**新增一个实现类 + 一条配置**，不改业务代码 |

### FR-4 知识库与 RAG（P0）

| 用户故事 | 作为**应用配置者**，我要上传文档后让应用能基于文档内容作答 |
|---|---|
| AC-4.1 | 支持上传 TXT / Markdown / PDF / Word，自动解析、分片、向量化 |
| AC-4.2 | 分片策略可配（按段落 / 固定字数 / 重叠窗口），分片结果可预览与手工调整 |
| AC-4.3 | 入库为异步任务，可查看进度、失败原因、支持重试 |
| AC-4.4 | 检索返回命中分片并**附带来源引用**，前端可展示引用出处 |
| AC-4.5 | 检索支持元数据过滤与相似度阈值 |
| AC-4.6 | **租户隔离**：任何检索强制注入 `tenant_id` 过滤，跨租户内容不可见 |
| AC-4.7 | 支持知识库检索调试台：输入问题查看命中分片与相似度分数 |

### FR-5 工具与 MCP（P1）

| 用户故事 | 作为**应用配置者**，我要给应用挂载外部工具，让模型能调用真实能力 |
|---|---|
| AC-5.1 | 支持三类工具：本地 `@Tool` Bean、HTTP 工具、MCP 工具，统一注册为 `ToolCallback` |
| AC-5.2 | MCP **Client**：支持 stdio（`npx` 拉起）与 SSE 两种传输，可配置多个外部 Server |
| AC-5.3 | MCP **Server**：平台自建服务，按 `service` / `sse` / `stdio` 三模块拆分，对外暴露平台能力 |
| AC-5.4 | 工具调用支持超时、失败重试上限、入参出参审计 |
| AC-5.5 | 工具可绑定单个应用，也可全局共享 |
| AC-5.6 | **已知坑规避**：外部 SSE 型 MCP 必须用配置类代码方式集成；stdio 必须指定 UTF-8 编码 |

### FR-6 会话与记忆（P0）

| 用户故事 | 作为**终端用户**，我希望对话能记住上下文 |
|---|---|
| AC-6.1 | 支持多会话，会话按用户隔离，可重命名 / 删除 / 归档 |
| AC-6.2 | 记忆策略可配：窗口条数、是否启用摘要压缩 |
| AC-6.3 | 记忆持久化到 MySQL / Redis，服务重启不丢失 |
| AC-6.4 | 消息落库并记录 Token 用量、耗时、模型、引用来源 |

### FR-7 Agent 编排（P1）

| 用户故事 | 作为**应用配置者**，我要让应用能自主拆解并执行多步任务 |
|---|---|
| AC-7.1 | ReAct 循环：思考 → 行动 → 观察，直到 `done` 或达到预算上限 |
| AC-7.2 | 对齐课程设计：**Thinking 与 Action 来自同一条 AssistantMessage**，**Observation 独占 UserMessage**，维护**端上状态上下文** |
| AC-7.3 | 支持规划型 Agent：任务拆解为子任务链，逐个执行并拼接结果 |
| AC-7.4 | 每个步骤产生事件帧（`agent.step`），前端可实时看到执行过程 |
| AC-7.5 | 支持**中断**：用户点击停止后能真正取消后续步骤 |
| AC-7.6 | 三重预算：最大步数、最大 Token、最大耗时，任一超限即终止并返回已得结果 |
| AC-7.7 | 支持检查点（checkpoint），任务可断点恢复 |

### FR-8 提示词管理（P1）

| 用户故事 | 作为**应用配置者**，我要统一管理提示词并支持版本回滚 |
|---|---|
| AC-8.1 | 提示词模板支持变量占位符（如 `{now}`），运行时渲染 |
| AC-8.2 | 每次修改生成新版本，可回滚、可对比 |
| AC-8.3 | 支持灰度：按比例或按用户分流到不同版本 |

### FR-9 产物管理（P1）

| 用户故事 | 作为**终端用户**，我要查看 Agent 生成的表格 / 图表 / 网页 |
|---|---|
| AC-9.1 | Agent 生成的产物落盘并关联到消息 |
| AC-9.2 | 支持在线预览与下载，产物按租户隔离 |
| AC-9.3 | 存储抽象为 `ArtifactStore`，本地磁盘可替换为对象存储 |

### FR-10 安全护栏（P1）

| 用户故事 | 作为**租户管理员**，我要限制模型的回答范围，避免幻觉与越界 |
|---|---|
| AC-10.1 | 输出侧：回答必须基于检索到的知识库内容，未命中时明确告知而非编造 |
| AC-10.2 | 敏感信息（如内部 ID）禁止出现在回复中 |
| AC-10.3 | 越界问题按配置的引导话术拒绝并引导 |
| AC-10.4 | 规则可配置、可开关 |

### FR-11 配额、审计与可观测（P0/P1）

| 用户故事 | 作为**租户管理员**，我要看清用量并对超限行为限流 |
|---|---|
| AC-11.1 | 配额维度：请求数 / Token / 文档数 / Agent 任务数，周期可配（日 / 月） |
| AC-11.2 | 超限返回明确错误码并拒绝服务 |
| AC-11.3 | 审计日志记录：谁、何时、哪个应用、用了哪个模型、多少 Token、耗时 |
| AC-11.4 | 全链路 TraceId 贯穿，可串起一次请求的检索 / 工具 / 模型调用 |
| AC-11.5 | 提供用量看板（租户 / 应用 / 用户维度） |

### FR-12 开放 API 与前端（P0）

| 用户故事 | 作为**开发者**，我要通过 API 集成；作为**终端用户**，我要在 H5 或小程序对话 |
|---|---|
| AC-12.1 | 对话接口支持流式：H5 走 **SSE**，微信小程序走 **NDJSON Chunked**，Agent 长任务走 **WebSocket** |
| AC-12.2 | 统一事件帧格式，事件类型覆盖：`msg.start / token / tool.start / tool.end / rag.sources / agent.step / artifact / msg.end / error / ping` |
| AC-12.3 | 前端页面：对话页、应用配置、知识库管理、模型管理、工具与 MCP、Agent 任务时间线、提示词、监控、租户与用户管理 |
| AC-12.4 | 对话页能力对齐课程设计稿：富文本 / 卡片 / 链接、推荐问题、下拉加载、语音输入与播放、历史对话、未登录与已登录态 |
| AC-12.5 | 管理端页面放在小程序**分包**中，避免主包超限 |

## 2. 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-1 | 性能 | 首 Token 延迟（TTFT）P95 < 2s（不含模型自身耗时）；知识检索 P95 < 300ms |
| NFR-2 | 并发 | 单实例支持 200 并发长连接；流式连接可水平扩展 |
| NFR-3 | 安全 | 密钥加密存储；所有输出脱敏；越权访问零容忍并有测试覆盖 |
| NFR-4 | 可用性 | 模型供应商故障时自动降级；单实例故障不影响其他实例 |
| NFR-5 | 可扩展 | 模型 / 向量库 / 工具来源 / Agent 策略 / 记忆存储 均为接口驱动，替换不改业务代码 |
| NFR-6 | 可观测 | 指标、日志、链路三件套齐备；每次调用可追溯到 Prompt |
| NFR-7 | 成本可控 | 每次调用记录 Token 与费用估算；配额可硬限流 |
| NFR-8 | 可维护 | 模块依赖关系由 ArchUnit 自动化卡口，违反即构建失败 |
| NFR-9 | 可移植 | 一条 `docker compose up` 可拉起全套依赖（含 Redis Stack） |

## 3. 一期范围界定

### 3.1 一期（M0 ~ M2）必须交付

- 多租户骨架：租户 / 用户 / 角色 / API Key / 鉴权拦截
- 模型网关：至少 2 家供应商可切换 + 场景选模 + 降级
- 对话闭环：非流式 + 三种流式通道
- 知识库与 RAG 全链路：上传 → 解析 → 分片 → 向量化 → 检索 → 引用
- 内置教育助手示例模板（含演示知识库与提示词）
- 基础审计与用量记录

### 3.2 二期（M3 ~ M5）

- 工具中心与 MCP 双向
- Agent 内核（ReAct + 规划执行 + 多 Agent 协同）
- 产物管理、安全护栏、配额硬限流、可观测看板

### 3.3 明确不做（本期）

| 不做 | 说明 |
| --- | --- |
| 垂直业务系统 | 只做中台；教育助手仅作为内置模板 |
| 模型训练 / 微调 | 只做接入与编排 |
| 自建向量数据库 | 复用 Redis Stack，保留抽象 |
| 原生移动 App | H5 + 小程序已覆盖多端需求 |
| 复杂多智能体编排 | M4 先打通 ReAct 与规划执行 |
| 多语言 / 国际化 | 一期仅中文 |
