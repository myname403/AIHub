# 06 · 里程碑与迭代计划

> 原则：**一期先跑通最小闭环，再逐层叠加**。每个里程碑都必须有可验证的完成标志（DoD）。

---

## 1. 总览

| 阶段 | 主题 | 核心目标 | 覆盖课程知识点 |
| --- | --- | --- | --- |
| **M0** | 工程地基 | 多模块骨架 + 多租户鉴权 + 本地环境 | 工程化、多租户 |
| **M1** | 对话闭环 | 模型网关 + 对话 + 流式三通道 | **第一章**：ChatClient、Advisor、ChatMemory、结构化输出、可观测 |
| **M2** | 知识增强 | RAG 全链路 + 内置示例应用 | **第一章**：ETL、VectorStore、RAG Advisor、元数据过滤｜**第二章**：业务助手 |
| **M3** | 工具与协议 | 工具中心 + MCP 双向 | **第三章** 全部 |
| **M4** | 自主智能体 | Agent 内核 + 多 Agent 协同 + 产物 | **第四章** MyManus |
| **M5** | 生产化 | 配额硬限流 + 可观测 + 开放 API + 浏览器控制 | 综合深化 |

---

## 2. M0 · 工程地基

**目标**：把分层骨架和租户体系立起来，让后续所有开发有统一落点。

**涉及模块**：`aihub-parent` / `aihub-common` / `aihub-api`（Feign 契约）/ `aihub-gateway` / `aihub-platform-service` / `aihub-ai-service`

> 服务边界与中间件用法见 **07-微服务与中间件设计.md**。

**任务清单**
1. 创建 Maven 多模块工程，配置 BOM 与依赖锁定（Spring Boot / Spring Cloud / Spring Cloud Alibaba / Spring AI）
2. 三个可启动服务骨架：gateway(8080) / platform-service(8081) / ai-service(8082)
3. `aihub-ai-service` 内部落地 `domain` 的实体与全部 SPI 接口（先定义，暂不实现）
4. 接入 MyBatis-Plus + Flyway，建 `sys_*` 与核心 `ai_*` 表
5. 实现认证（JWT）+ 租户解析 + `TenantContext` + MyBatis 租户拦截器
6. **Feign 拦截器自动透传 `tenantId`**，服务端强制校验
7. **Nacos**：注册中心 + 配置中心；基础设施配置（超时 / 限流 / 开关 / 线程池）迁入并验证热更新
8. **Sentinel**：网关层限流 + 规则持久化到 Nacos
9. 统一响应体、错误码、全局异常处理
10. 引入 ArchUnit，写入依赖规则并接入构建（作用域：每个服务内部）
11. `docker-compose.yml`：MySQL 8 + Redis Stack + Nacos 3.0.3 + Sentinel Dashboard；Redis 健康检查断言 `MODULE LIST` 含 `search`
12. 输出文档包（01~07）

**交付物**：三个服务可启动、通过 ArchUnit 校验、一条命令拉起全部依赖

**完成标志（DoD）**
- `mvn clean install` 通过，ArchUnit 依赖规则全绿
- `docker compose up` 后 MySQL、Redis Stack、Nacos 均健康
- 三个服务在 Nacos 中注册成功，gateway 能路由到后端服务
- 在 Nacos 改一个配置（如超时），应用**无需重启**即生效
- 登录接口可返回 JWT，未带 Token 访问受保护接口返回 401
- 跨租户访问测试失败（即被正确拦截）

## 3. M1 · 对话闭环

**目标**：跑通"能对话、能流式、能换模型"的最小可用闭环。

**涉及模块**：`aihub-infra-ai` / `application` / `web`

**任务清单**
1. `ModelGateway` + `ChatModelResolver`：先接 OpenAI 兼容 + 火山方舟 DeepSeek，后续补通义与 Ollama
2. 密钥加密存储；`ai_model` / `ai_model_route` 配置化；场景选模与降级
3. `ChatClientFactory` + `ChatClientSpec`：按应用配置动态装配，带缓存
4. Advisor 链：记忆 Advisor、审计 Advisor（**同时实现 `StreamAroundAdvisor`**）
5. `ConversationMemoryStore`：窗口记忆 + 持久化到 MySQL/Redis
6. 三种 `StreamSink`：SSE（H5）、NDJSON Chunked（小程序）、WebSocket
7. 前端 uniapp 对话页：流式打字机、历史会话、引用占位

**完成标志（DoD）**
- 切换模型配置后无需重启即可生效
- H5 能看到逐字输出；微信小程序真机验证 chunked 分块正常（含半包处理）
- 主模型不可用时自动降级并在审计日志留痕
- 刷新页面后会话历史与记忆不丢失
- 每次调用在 `ai_usage_record` 留下 Token 与耗时

---

## 4. M2 · 知识增强（RAG）

**目标**：让应用能基于自有文档作答，并落地课程的"业务助手"形态。

**涉及模块**：`infra-ai`（ETL）/`infra-persistence` / `application` / `web` / 前端

**任务清单**
1. ETL 流水线：文档解析（TXT/MD/PDF/Word）→ 清洗 → 分片（策略可配）
2. 向量化与入库：批量 Embedding → Redis Stack；异步任务 + 进度 + 重试
3. `VectorStoreProvider` + `KnowledgeRetriever` + `RetrievalStage` 责任链
4. **租户隔离四道防线**落地 + 跨租户自动化测试
5. 检索调试台：输入问题查看命中分片与相似度
6. 消息引用来源落库（`ai_message_reference`）并在前端展示
7. `SafetyGuard` 初版：基于课程提示词的防幻觉约束
8. **内置教育助手示例模板**：导入 10 门课程演示数据 + 四技能提示词 + `queryCourseById` / `prePlaceOrder` 工具示例

**完成标志（DoD）**
- 上传 PDF 后可检索并作答，回答附带可点击的引用来源
- 跨租户测试用例通过（A 租户检索不到 B 租户数据）
- 未命中知识库时按配置话术明确告知，不编造
- 内置模板一键复制后即可对话演示

---

## 5. M3 · 工具与 MCP

**目标**：打通工具调用，并把平台能力以 MCP 暴露出去。

**涉及模块**：`infra-ai` / `aihub-mcp-service` / `aihub-mcp-sse` / `aihub-mcp-stdio` / 前端

**任务清单**
1. `ToolRegistry` + `ToolProvider`：本地 `@Tool`、HTTP 工具统一注册
2. MCP **Client**：stdio（`npx` 拉起）与 SSE 两种传输，多 Server 并存
3. MCP 工具转为 `ToolCallback` 并挂到 `ChatClient`
4. MCP **Server**：`service` / `sse` / `stdio` 三模块，暴露平台对话与知识检索能力
5. 工具调用超时、重试上限、入参出参审计（`ai_tool_call_log`）
6. 前端工具管理页 + 对话中展示工具调用过程

**已知坑（课程已踩）**
- 外部 SSE 型 MCP 必须用**配置类代码方式**集成，仅配 url 不生效
- stdio 必须指定 **UTF-8** 编码，否则中文参数乱码

**完成标志（DoD）**
- 挂载一个外部 MCP Server 后，模型能自主调用其工具
- 平台自建 MCP Server 可被第三方客户端发现并调用
- 工具调用超时被正确中断并有日志记录

---

## 6. M4 · 自主智能体

**目标**：实现对齐课程 MyManus 的 Agent 内核。

**涉及模块**：`infra-ai` / `application` / `web` / 前端

**任务清单**
1. `Agent` / `BaseAgent` / `ReActBaseAgent` 抽象（对齐课程类层次）
2. `AgentRegistry`（对应课程 `AgentFactory`）+ 按名查找
3. `AgentContext` 端上状态上下文
4. `ReActLoop`：**Thinking + Action 同消息返回**（thinking 作固定参数）、**Observation 独占 UserMessage**、`done` 终止
5. `Planner` + `SubTaskChain`：任务拆解与结果拼接
6. 专用 Agent：规划 Agent + 通用执行 Agent（表格 / 图表 / HTML）
7. `ArtifactStore`：产物落盘、预览、下载
8. 三重预算：最大步数 / 最大 Token / 最大超时；支持中断与 checkpoint 恢复
9. WebSocket 推送 `agent.step` 事件；前端任务时间线

**完成标志（DoD）**
- 多步任务能被拆解并逐步执行，前端时间线可见每一步
- 触发 `done` 或预算上限后正确终止
- 用户点击停止后后续步骤真正取消
- 生成的表格/图表可在线预览

---

## 7. M5 · 生产化

**目标**：补齐生产要素，让项目达到可交付水准。

**任务清单**
1. 配额硬限流（请求数 / Token / 文档 / 任务）+ 超限错误码
2. 可观测：Micrometer 指标、TraceId 全链路、用量看板
3. 开放 API：API Key 管理、接口文档、限流
4. 审计日志与脱敏完善
5. （可选增强）浏览器控制：接入 Playwright MCP 或自建浏览器工具，实现页面标注
6. （可选）多智能体协同

**完成标志（DoD）**
- 配额超限被拒绝且返回明确错误码
- 一次请求可用 TraceId 串起检索 / 工具 / 模型调用
- 用量看板可按租户 / 应用 / 用户维度查看
- 密钥在任何日志与响应中不出现明文

## 8. 阶段依赖

```
M0 ──▶ M1 ──▶ M2 ──▶ M3 ──▶ M4 ──▶ M5
 │      │      │
 │      │      └── RAG 依赖 M1 的 Advisor 链与流式
 │      └── 对话依赖 M0 的租户与鉴权
 └── 所有阶段都依赖 M0 的模块骨架与依赖卡口
```

说明：M3 与 M4 的顺序可调整——若希望更早看到 Agent 效果，可先做 M4 的 ReAct（不依赖 MCP），把 MCP 放后。

## 9. 风险与缓解（贯穿各阶段）

| # | 风险 | 阶段 | 缓解 |
| --- | --- | --- | --- |
| R1 | Spring AI 1.1.x `initialize-schema` 默认 false | M2 | DDL 交 Flyway；向量索引由 Provider 显式创建 |
| R2 | Redis Stack 缺失导致向量不可用 | M0 | 用 `redis/redis-stack-server` 镜像 + `MODULE LIST` 健康检查 |
| R3 | 向量维度与模型不匹配 | M2 | `vector_dim` 强校验；换模型走别名切换流程 |
| R4 | **租户隔离遗漏** | M2 | 四道防线 + 跨租户自动化测试 |
| R5 | 小程序流式 gzip / 半包 | M1 | 禁 gzip、按 `\n` 缓冲、真机验证 |
| R6 | Agent 死循环 / 成本失控 | M4 | 三重预算 + 重复调用检测 + 前端可真正取消 |
| R7 | MCP stdio 中文乱码 | M3 | 指定 UTF-8 编码 |
| R8 | 外部 SSE MCP 只配 url 不生效 | M3 | 用配置类代码方式集成 |
| R9 | Advisor 在流式下不生效 | M1 | 旁路 Advisor 实现 `StreamAroundAdvisor`，`call()` / `stream()` 双路径测试 |
| R10 | 架构随迭代腐化 | 全程 | ArchUnit 依赖卡口常驻 CI |
