# 01 · 项目总览与术语表

| 项 | 值 |
| --- | --- |
| 项目代号 | **AIHub** |
| 项目定位 | 多租户 · 通用 AI 能力中台 |
| 后端 | Java 17 + Spring Boot 3.5.x + Spring AI 1.1.x |

---

## 1. 一句话定位

**AIHub 是一个多租户的「AI 能力中台」**：它自身不绑定任何垂直业务，而是把大模型能力（对话、RAG、工具、Agent）抽象成**可配置、可编排、可计量、可观测**的平台能力，对外以「开放 HTTP API」+「管理控制台（H5 / 微信小程序）」两种形态交付。

业务方只是它的**消费者**——通过在平台上配置一个「应用（助手）」来组装出自己需要的 AI 能力。

> 一句话概括分层设计目标：**模型可换、知识可插、工具可注册、Agent 可编排、一切可按租户计量与审计。**

---

## 2. 背景与目标

### 2.1 背景

本项目源自《Java+AI 智能应用开发（线上训练营）v1.0》课程知识的工程化落地。课程覆盖了 Spring AI 基础、RAG、Tool Calling、MCP 双向集成与自主智能体（MyManus），但各章节以独立 Demo 形式呈现，缺少统一的工程架构。

直接把这些 Demo 拼在一起会产生三个问题：模型硬编码、能力无法复用、没有租户与成本边界。因此需要一层**中台化重构**：把课程里的技术点沉淀为平台能力，用配置代替硬编码，用接口隔离实现细节。### 2.2 项目目标

| 类型 | 目标 |
| --- | --- |
| 技术目标 | 把课程知识点全部落到生产级工程实践中：Spring AI 基础、RAG、Tool Calling、MCP 双向、自主 Agent、可观测性 |
| 架构目标 | 严格分层解耦 + 全面 SPI 抽象，任何底层实现（模型 / 向量库 / 工具 / Agent 策略 / 记忆存储）可替换而不改业务代码 |
| 工程目标 | 多租户 SaaS 形态，具备身份、配额、审计、可观测等生产要素 |
| 演进目标 | 分阶段推进，一期跑通最小闭环，后续可持续叠加能力而不推倒重来 |

## 3. 能力地图

平台对外提供 **12 个能力域**：

| # | 能力域 | 对外提供的能力 | 关键扩展点 |
| --- | --- | --- | --- |
| 1 | **模型网关** | 统一 ChatModel / EmbeddingModel 解析；支持 OpenAI 兼容 / 火山方舟 DeepSeek / 通义 DashScope / 本地 Ollama；按场景（chat / rag / embed / agent-plan）选模型；主备降级 | `ModelGateway` · `ChatModelResolver` · `ModelSelectionStrategy` |
| 2 | **应用（助手）编排** | 一个 App = 系统提示词 + 模型 + 知识库 + 工具集 + Agent 策略 + Advisor 链 的配置组合 | `ChatClientFactory` · `ChatClientSpec` |
| 3 | **知识库 / RAG** | 文档上传 → 解析 → 分片 → 向量化 → 入库；检索支持查询重写、意图路由、向量召回、元数据过滤、重排、引用溯源 | `KnowledgeRetriever` · `VectorStoreProvider` · `Reranker` |
| 4 | **工具中心** | 本地 `@Tool` 工具、HTTP 工具、MCP 工具统一注册与调用；工具级超时 / 风控 / 审计 | `ToolRegistry` · `ToolProvider` |
| 5 | **MCP 双向** | 作为 **Client** 连接外部 MCP Server；作为 **Server** 把平台能力暴露出去（service / sse / stdio 三模块） | `McpClientManager` · `aihub-mcp-*` |
| 6 | **Agent 编排** | 同一内核多策略：ReAct → 规划执行 → 多 Agent 协同；步骤级事件流、可中断可恢复、预算控制 | `AgentStrategy` · `AgentRegistry` · `ReActLoop` |
| 7 | **会话记忆** | 窗口记忆、摘要压缩、持久化到 MySQL / Redis；按会话 / 用户维度隔离 | `ConversationMemoryStore` |
| 8 | **提示词管理** | 模板 + 变量 + 版本 + 灰度；运行时渲染 | `PromptRenderer` · `PromptRepository` |
| 9 | **产物管理** | Agent 生成的表格 / 图表 / HTML 落盘、在线预览、下载 | `ArtifactStore` |
| 10 | **安全护栏** | 防幻觉与越界拦截（源自课程「天机 AI 助手」提示词约束），规则可配置 | `SafetyGuard` |
| 11 | **可观测与成本** | TraceId 贯穿、Micrometer 指标、Token / 耗时 / 成本埋点、Prompt 审计、脱敏 | Advisor（OBSERVABILITY / LOG / AUDIT） |
| 12 | **多租户与配额** | 租户 / 用户 / 角色 / API Key；按租户-用户-应用-周期维度的请求数 / Token / 文档 / 任务配额与硬限流 | `TenantContext` · `QuotaService` |

## 4. 角色定义

| 角色 | 说明 | 主要动作 |
| --- | --- | --- |
| **平台管理员** | 平台运营方，跨租户 | 创建租户、分配配额、查看全局监控、灰度模型 |
| **租户管理员** | 某租户的负责人 | 管理本租户用户与角色、配置模型密钥、查看本租户用量与审计 |
| **应用配置者** | 搭建 AI 应用的人 | 创建应用（助手）、绑定知识库 / 工具 / 提示词 / Agent 策略、调试与发布 |
| **终端用户** | 最终对话使用者 | 发起对话、查看引用来源、反馈点赞点踩、上传个人文档 |
| **开发者（外部业务方）** | 通过开放 API 集成 | 申请 API Key、调用对话 / 检索 / Agent 接口、接收流式事件 |

## 5. 术语表

| 术语 | 英文 / 缩写 | 含义 |
| --- | --- | --- |
| 租户 | Tenant | 资源隔离的最外层单位。所有业务数据带 `tenant_id` |
| 应用 / 助手 | App / Assistant | 一组 AI 能力的配置组合，是平台上可被消费的最小单元 |
| 模型供应商 | Provider | OpenAI 兼容、火山方舟、DashScope、Ollama 等 |
| 场景选模 | Scenario Routing | 按用途（聊天 / 检索 / 嵌入 / 规划）选择不同模型 |
| 知识库 | Knowledge Base | 一组文档的集合，是 RAG 的检索范围单位 |
| 分片 | Chunk | 文档切分后的最小检索单元 |
| 向量索引别名 | Index Alias | Redis 索引的逻辑名，用于零停机重建（`v{n}` + alias） |
| 工具 | Tool | 可被模型调用的函数；来源包括本地 Bean、HTTP、MCP |
| MCP | Model Context Protocol | 模型上下文协议，标准化 LLM 与外部工具的通信 |
| Advisor | Advisor | Spring AI 的拦截链，用于在模型调用前后织入横切逻辑 |
| ReAct | Reasoning + Acting | 思考 → 行动 → 观察 的循环执行范式 |
| 端上状态上下文 | AgentContext | Agent 执行过程中维护的环境状态（对齐课程「系统状态上下文」） |
| 产物 | Artifact | Agent 生成并落盘的结果文件（表格 / 图表 / HTML） |
| 护栏 | SafetyGuard | 对输入 / 输出做合规与防幻觉拦截的组件 |
| 事件帧 | StreamEvent | 流式输出的最小单元，统一信封格式 |
| TraceId | TraceId | 贯穿一次请求全链路的追踪标识 |

## 6. 典型使用场景

1. **企业快速搭建领域助手**：配置者新建应用 → 上传产品手册建知识库 → 选模型 → 发布；终端用户在 H5 或小程序里对话，回答带引用来源。
2. **业务系统嵌入 AI 能力**：开发者申请 API Key → 调用开放 API（SSE 流式）→ 在自己的系统里渲染对话。
3. **工具增强的自动化任务**：给应用挂载 MCP 工具（如地图、搜索、内部接口）→ 开启 Agent 策略 → 用户下达多步任务 → 通过 WebSocket 观察每一步执行并可随时中断。
4. **能力对外复用**：把平台自身的「知识检索」「应用对话」通过自建 MCP Server 暴露出去，供其他 AI 应用集成。

## 7. 非目标（明确不做）

| 不做 | 原因 |
| --- | --- |
| 垂直业务外壳（电商 / 教育 / 客服等具体业务系统） | 平台定位是通用中台；课程中的「天机学堂助手」仅作为**内置示例应用模板**存在 |
| 自研大模型训练 / 微调 | 超出范围，只做模型接入与编排 |
| 自建向量数据库 | 复用 Redis Stack；保留抽象以便替换 |
| 一期的多智能体复杂编排 | 放到 M5 之后，M4 先打通 ReAct + 规划执行 |
| 移动端原生 App（iOS / Android） | 一期以 H5 + 微信小程序覆盖，App 端作为后续编译目标 |
