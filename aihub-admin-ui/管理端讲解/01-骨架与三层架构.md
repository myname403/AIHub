# 第一轮：骨架与三层架构

> 目标：pure-admin 目录几十个文件夹，其实只有三类东西：**框架自带的骨架**（layout/router/store 机制）、
> **AIHub 写的业务页**（views 下 7 个目录）、**两者之间的适配层**（api/、utils/http）。
> 认清哪些是"租来的房子"、哪些是"自己打的家具"，就不会迷路。

---

**开发日常 90% 时间在 views/**，但"页面为什么能出现、按钮为什么不显示、请求头里 token 哪来的"
这三个问题都发生在适配层——所以第二轮的链路是重点。

## 2. 三层各管一件事

### 层 1｜请求层（utils/http/index.ts）—— "信封拆包员"

- **请求拦截**：从 auth.ts 取 token，塞 `Authorization: Bearer xxx`（业务代码从不手动带 token）；
- **响应拦截**：后端永远返回 `R{code,message,data}`（HTTP 都是 200）——
  拦截器判断 `code===0` 就把 **data 直接顶上**（所以 `http.request()` 的返回值就是业务数据本身，
  没有 `.data.data` 套娃）；`code!==0` 弹 message 并 reject；
- **HTTP 层错误**：网络不通/网关 401/500——`status===401` 走统一的"登录过期"处理
  （对应记忆里那条开发规范：前端统一处理登录过期，页面代码不用各自写）；
- **一个例外要认识**：`api/user.ts`/`routes.ts` 里拉权限信息用的是**裸 Axios**（不走拦截器），
  手动 `res.data.data` 取值——因为那时 token 刚拿到还没 setToken，拦截器还取不到它。
  注释特意写了原因，这种"为什么这里破例"的注释值得学。

### 层 2｜路由层（router/ + api/routes.ts）—— "菜单变页面"

vue-router 本身只认"路由表"，pure-admin 的机制是：
登录后调用 `getAsyncRoutes()` 拿一批路由对象 → `addRoute` 动态注册 → 侧边栏按它渲染。
AIHub 的适配就一个函数 `toPureRoute`（递归）：

| 后端菜单字段 | pure-admin 字段 | 备注 |
|---|---|---|
| name | meta.title | 侧边栏文字 |
| icon（Element 图标名） | meta.icon（`ep/home-filled`） | toIconify 做了驼峰→kebab 转换 |
| sort | meta.rank | 菜单排序 |
| visible=0 | meta.showLink=false | 存在但不在菜单显示 |
| component（字符串） | 同名字段 | **关键约定**：字符串会被 utils.ts 的 addAsyncRoutes
  用 `import.meta.glob` 自动映射到 `src/views/<字符串>.vue`——所以**后端配 component 时必须和
  views 下的文件路径严格对上**，对不上就是白屏 |
| menuType=F | **过滤掉** | 按钮不进路由，只进权限码 |

### 层 3｜权限层（directives + store）—— "按钮级开关"

- 登录时后端把 `permissions: ["system:user:create", ...]` 存进 user store；
- 页面里 `v-perms="['system:user:create']"` 指令判断当前用户权限码集合，没有权限就**把 DOM 移除**；
- 注意：这只是"看不见"，**真正的拦截在后端 PermissionInterceptor**（403）——
  前端权限是体验，后端权限才是安全，两层用的是同一份 sys_menu.permission 数据源。

## 3. 开发环境网络拓扑（vite.config.ts）

```
浏览器 → http://localhost:8849（vite dev server）
              ├── /auth/**  ─ proxy 转发，同源无跨域
              └── /api/**   ─┘──▶ 网关 http://localhost:8080 ─▶ platform:8081 / ai:8082
```

- 前端页面里写的都是**相对路径**（`/auth/login`、`/api/platform/...`），代理规则在 vite.config.ts；
- 生产部署（deploy/nginx/default.conf.template）由 nginx 承担同样的反代角色；
- 网关的 globalcors 是**第二道保险**（给不走代理的直连场景兜底）——两层跨域方案并存是常见工程实践。
