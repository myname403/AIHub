# 第二轮：登录链路全景 + 记忆卡片 + 动手实验

## 1. 核心链路：从点"登录"到菜单出现（必背）

```
① login/index.vue 表单（租户码+用户名+密码+验证码，租户码默认 demo）
   → user store 的 loginByUsername → api/user.ts getLogin()
② POST /auth/login（vite 代理→网关→platform；网关白名单免 token）
   响应拦截器解 R 信封 → 拿到 {tenantId, userId, token, username}
③ 立刻用裸 Axios + 新 token 调 /api/platform/system/permission/info
   → 拿 {routes: 菜单树, permissions: 权限码[]} → cacheRoutes() 缓存
④ 组装 pure-admin 的 UserResult（roles/permissions/accessToken/expires）
   → setToken 存 localStorage → user store
⑤ 路由守卫发现"未初始化动态路由" → 调 api/routes.ts getAsyncRoutes()
   → toPureRoute 递归翻译（F 型过滤、icon 转换、component 字符串保留）
   → addRoute 注册 → 侧边栏渲染出菜单
⑥ 之后每个业务请求：http 拦截器自动带 Bearer token；
   网关验签→注入 X-Tenant-Id→后端按租户圈数据（后端链路见网关/平台讲解）
```

**三个"为什么"（追问高频）**：
- **为什么登录要发两个请求？** pure-admin 期望登录响应里就带 roles/permissions，
  而 AIHub 的 /auth/login 只返回 token——适配层补一个 permission/info 请求拼齐，
  框架代码零改动（适配层消化契约差异的实例）；
- **为什么刷新页面菜单不丢？** 内存里的 cachedMenuTree 刷新即空，
  getAsyncRoutes 检测空了会用 localStorage 的 token **重新拉** permission/info；
- **为什么 roles 写死 ["admin"]？** 路由可见性已由后端 routes 树决定（给什么菜单显什么），
  pure-admin 的 roles 字段只是它自己流程的占位需求——**不重复造第二套权限判断**。

## 2. 六张记忆卡片

**卡 1｜三层**：请求层拆信封、路由层翻菜单、权限层管按钮；业务页(view)不碰 token 不判 code。
**卡 2｜解包约定**：`http.request()` 返回的就是 data 本体（code!==0 已被拦截器变成 reject）。
**卡 3｜component 是字符串约定**：后端配 `system/user/index` → 前端找 `src/views/system/user/index.vue`，对不上=白屏。这是**前后端之间的隐式契约**，改文件路径要同步改菜单表。
**卡 4｜F 型按钮**：不进路由，只进 permissions 数组，喂 `v-perms` 指令。
**卡 5｜前端权限≠安全**：v-perms 只是隐藏 DOM；真防线是后端 PermissionInterceptor 的 403。删掉指令元素也不会获得权限。
**卡 6｜401 统一收口**：网关手写的 401（HTTP 层）走 axios error 分支 → 清 token 跳登录；业务 code=10002 走响应分支——两条路都要处理，utils/http 里都写了。

## 3. 动手实验

**实验 1｜看动态路由的"出生"**
F12 Network + 登录 → 找到 `permission/info` 请求 → 复制响应里 routes 树；
对照侧边栏：删掉 localStorage 的 token 刷新 → 回登录页（守卫拦截）；
再对照 Console 执行 `usePermissionStoreHook().handleWholeMenus([])` 相关路由数组——菜单=路由表=后端数据，一条线看到底。

**实验 2｜按钮权限实证**
系统管理-角色页新建一个"只读角色"（只勾 query 类菜单）→ 建用户绑该角色 → 用它登录：
新增/删除按钮消失（v-perms 生效）→ **但直接 curl 调创建接口**（带该用户 token）→ 后端 403。
卡 5 的完整证据链：前端藏按钮是体验，后端 403 才是安全。

**实验 3｜改密码后旧 token 还能用吗？**
登录后复制 token 到 curl 用 → 修改自己密码 → 再用旧 token 请求 → **仍然有效**（JWT 无状态，改密码不吊销已发令牌，2 小时自然过期）。
思考：要即时失效该怎么做？（登录时把 userId+密码版本写入 claims / 维护 token 黑名单——本项目未做，属已知边界，可写进面试"改进项"）。

## 4. 自测五问

1. 新写一个业务页要动几个地方？（views 建组件 + 后端菜单表加 C 型记录(component 对上路径) + 需要按钮权限就加 F 型 + v-perms）
2. 为什么 api/user.ts 里用裸 Axios？（token 未 set，拦截器取不到）
3. refreshTokenApi 为什么是假的？（AIHub 暂无独立刷新令牌，复用原 token 顺延过期——注释诚实标注）
4. 菜单 visible=0 和 status=0 的区别？（visible：有权限但不显示；status=0：停用，getUserMenus 直接过滤掉）
5. 页面白屏且控制台报组件找不到，第一查什么？（菜单表 component 与 views 实际路径是否对上——卡 3）
