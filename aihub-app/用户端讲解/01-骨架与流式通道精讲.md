**条件编译是 uni-app 的魂**：`// #ifdef H5 ... // #endif` 在编译期按目标平台裁剪代码——
同一个文件，H5 包里是 fetch，小程序包里是 uni.request。不是运行时 if，是**发两份不同的代码**。

## 2. common/stream.js 逐段精讲（NDJSON 双端通道）

### 2.1 为什么不用 SSE？

H5 本来可以用 EventSource，但**它不能带自定义 Header**（Authorization 塞不进去）；
小程序压根没有 EventSource。所以后端专门开了 `NdjsonStreamSink`（每行一个 JSON 事件帧），
前端两端统一按"行协议"解析——**协议迁就最弱的客户端，一套格式通吃两端**。

事件帧类型（和后端 StreamEvent 一一对应）：
`msg.start / token / rag.sources / agent.step / artifact / msg.end / error`

### 2.2 半包处理（流式编程的第一课）

网络块到达边界不会照顾"一行"这个语义——一块可能包含 1.5 行：

```js
const handleChunk = (text) => {
  buffer += text
  const lines = buffer.split('\n')
  buffer = lines.pop() || ''   // 最后一段可能不完整，退回缓冲区等下一块
  for (const line of lines) emitLine(line)   // 只消费"确定完整"的行
}
```

**flush() 是另一个坑的补丁**：服务端最后一帧可能不带 `\n`——
不冲刷缓冲区，最后一条消息就"永远差半句"（注释里写了症状：最后一条消息渲染不出来）。
> 记忆：`pop` 留半包，`flush` 收尾巴。所有行协议客户端都是这两板斧。

### 2.3 两端实现对照

| | H5 | 小程序 |
|---|---|---|
| 通道 | `fetch` + `res.body.getReader()` 循环读 | `uni.request({enableChunked:true})` + `task.onChunkReceived` |
| 解码 | 原生 `TextDecoder('utf-8')` | **没有 TextDecoder → 手写 `arrayBufferToUtf8`**（1~4 字节 UTF-8 全手工，中文 3 字节） |
| 中断 | `AbortController.abort()` | `task.abort()` |
| 401 | res.status===401 → handleUnauthorized | statusCode===401 → 同一函数 |

### 2.4 "停止生成"的完整真相（最容易被忽略的分布式细节）

```js
abort()  // 只是客户端断开连接——服务端还在跑、还在烧 token！
```
所以 chat.vue 的 stop() 是**两步**：① abort 本地流（不再渲染）；
② `POST /api/ai/agent/cancel`（通知服务端在步骤边界终止 → AgentCancelRegistry 置取消位）。
**"客户端断开 ≠ 服务端停止"**——凡是"能停止"的流式系统都必须有第二条信令通道，
这正好接上 AI 服务讲解链路 3 的 CANCELED 状态。

## 3. request.js 与登录态（薄但要有）

- `uni.request` 包一层：URL 前缀拼 config.baseUrl、自动 `Authorization: Bearer <token>`；
- 解 R 信封：code===0 resolve(data)，否则 toast message + reject；
- 401 → `handleUnauthorized()`：清 token、提示"登录已过期"、reLaunch 回登录页
  （对应开发规范记忆"前端统一处理登录过期"——页面代码零感知）；
- token 过期时间对齐后端 `jwt-expire-seconds=7200`（无独立刷新令牌，过期即重新登录）。

## 4. 页面层速览（chat.vue 是唯一复杂页）

- 消息数组存响应式 data，流式 token 事件**逐帧追加到最后一条 assistant 消息**
  （注意 Vue3 响应式陷阱记忆：更新数组内对象属性要用整体替换或响应式安全写法，否则视图不动）；
- 场景切换 chat/rag/agent 就是改请求体的 `scene` 字段——路由逻辑全在后端
  （前端不感知模型选择，除非用 modelCode 显式指定，空=走管理端配置的场景路由）；
- `rag.sources` 事件渲染"引用来源"卡片、`artifact` 事件渲染产物预览链接——
  **前端只是事件的分发器，业务复杂度都留在后端**（瘦客户端原则）。
