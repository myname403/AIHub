# 第三轮：记忆卡片与动手实验

## 1. 总口诀

**"四层单向朝 domain，三链各有各的闸"**

| 口诀 | 含义 |
|---|---|
| 四层 | web 开门 / application 指挥 / domain 定规矩 / infra 干活 |
| 单向朝内 | application 只 import domain+common，ArchUnit 卡死 |
| 对话链的闸 | 配额前置扣次数、token 事后补扣、失败进发件箱 |
| RAG 链的闸 | 入库带租户（源头）、检索 TenantGuard（出口） |
| Agent 链的闸 | 三重预算 + 取消登记 + 产物走引用不走内联 |

## 2. 六张卡片

**卡 1｜为什么不拆微服务？** 流式跨服务传递/长任务状态/分布式事务三座大山——边界用包画、进程就一个（模块化单体）。
**卡 2｜SPI 二十个接口是干嘛的？** 内层声明"我要什么"（ModelGateway/StreamSink/…），外层实现"怎么给"（Db*/Redis*/SpringAi*）——换实现不改编排，单测塞假货。
**卡 3｜流式三防头**：`Content-Encoding: identity`（防 gzip 缓冲）、`X-Accel-Buffering: no`（防 nginx 攒包）、`Cache-Control: no-transform`（防中间层改造）——少一个，逐 token 就变"憋大招"。
**卡 4｜异常→事件**：流式通道上响应头已发，抛异常=静默失败；一切错误必须翻成 StreamEvent.error 再 close。
**卡 5｜Outbox 两级降级**：上报失败→日志放行+落库；后台 30s 扫表重投≤3 次；兜底自身失败仍只记日志（防次生异常盖住原始错误）。
**卡 6｜热更新三条件**：@ConfigurationProperties + 可变 JavaBean(setter) + AiRuntimeConfiguration 登记——record 会静默失去热更能力。

## 3. 动手实验

**实验 1｜看流式三防头（30 秒）**
管理端登录后 F12 → Network 找 `/api/ai/chat/stream` 请求 → Response Headers 里找到
`Content-Encoding: identity` 和 `X-Accel-Buffering: no`；再看 Response 标签页内容随时间**逐块增长**——这就是没被缓冲的证据。

**实验 2｜配额闸门实弹（和 platform 文档实验 3 联动）**
给 demo 配 `request/day=3` 后第 4 次对话：H5 页面应收到一个 **error 事件**（而不是 HTTP 报错）——
验证卡 4："异常→事件"翻译真实存在。看 ai-service 日志应无 ERROR（降级路径只 WARN）。

**实验 3｜发件箱肉眼可见**
对话进行中把 platform 服务停掉（IDEA 里停 8081）→ 再发一条对话 →
对话**仍然成功**（降级放行）→ 查库：
```sql
SELECT status, event_type, retry_count FROM aihub_ai.ai_event_outbox ORDER BY create_time DESC LIMIT 5;
```
出现 status=0 的待投记录；重启 platform 后 30 秒内变 status=1——Outbox 最终一致，全程直播。

**实验 4｜工具审计**
对话里问"现在几点"（TimeTools 会被模型自主调用）→
查 `SELECT tool_name, source, duration_ms FROM aihub_ai.ai_tool_call_log ORDER BY id DESC LIMIT 5;`
→ 每次模型调工具都有一条账（AuditedToolCallback 记的），前端工具面板/指标都吃这张表。

**实验 5｜RAG 租户隔离**
用租户 `12` 的账号上传一个私有文档入库 → 切回 demo 租户对话问同样内容 →
答不出来（检索 TenantGuard 过滤了别的租户向量）。**这一条测的是"知识库的墙"**。

## 4. 自测六问

1. 改某应用的系统提示词为什么不立刻生效？（ChatClient 缓存 TTL 60s，惰性过期轮换）
2. Agent 场景为什么先扣 task 而不是和对话一样扣 request？（多步执行成本高一个量级，需要独立额度维度）
3. PlanningAgent 挂了个子 Agent 把 token 花超，预算拦得住吗？（拦得住——budget 同一引用共享计数）
4. 小程序为什么不能用 SSE？（uni-app 微信端无 EventSource；NdjsonStreamSink + enableChunked 是替代通道）
5. 模型 Key 在库里是什么形态？（AES-GCM 密文，运行时解密构建 ChatModel——对照 common 讲解"三把锁"）
6. `/api/ai/smoke` 这类接口干嘛的？（M0 冒烟：验证网关→租户上下文→本服务整条链路通，健康检查用）
