# 第二轮：记忆卡片与动手实验

## 1. 总口诀

**"一厨两窗四工具，错不变异靠文字"**

| 口诀 | 含义 |
|---|---|
| 一厨 | mcp-service 业务核心（工具实现只写一次） |
| 两窗 | sse（webmvc starter）/ stdio（core starter）两个传输薄壳 |
| 四工具 | list_applications / list_knowledge_bases / search_knowledge / ask |
| 错不抛 | AiHubCallException 被吃掉转人话（面向模型编程） |
| 变异靠文字 | 工具全返回 String，纯文本跨客户端最稳 |

## 2. 六张卡片

**卡 1｜stdio 版为什么 stdout 是命根子？**
stdout=JSON-RPC 协议通道。banner 会打乱第一帧（`banner-mode: off`）、日志必须走 stderr（专属 logback）、root=WARN（stderr 缓冲小，写满会阻塞）。症状记忆："一连上就崩且报错无指向性"。

**卡 2｜为什么 mcp-service 不依赖 aihub-common？**
common 传递 starter-web（Servlet 容器），stdio 进程里是纯负担；依赖最小化原则。代价=自带 ApiEnvelope 镜像，反而获得"服务端改内部 DTO 打不挂我"的隔离红利。

**卡 3｜两个 starter 的名字差异？**
`spring-ai-starter-mcp-server-webmvc`（带 web 传输：SSE/streamable）vs `spring-ai-starter-mcp-server`（core，无 web：stdio）。切换传输=换依赖，业务零改动——ADR-3。

**卡 4｜@Tool 的 description 为什么值 50 分？**
它是模型决定"用不用、怎么用"的唯一依据。本项目写法四要素：何时用/何时别用/结果怎么解读/不确定时的行为指引（交给用户确认，别瞎猜）。

**卡 5｜三层超时怎么咬合？**
宿主(≈60s) > MCP request-timeout(70s 配置上>HTTP) > HTTP timeout(60s)。原则：**外层>内层**，否则错误信息指不到真正卡住的层。

**卡 6｜多租户在 MCP 场景的落点？**
一个 MCP 实例 = 一个租户（`aihub.mcp.api-key` 决定），换 Key 即换租户；数据边界由网关 Key 鉴权兜底，通道 Bearer 门禁只管"谁能连"。

## 3. 动手实验

**实验 1｜SSE 版冒烟（不用装 MCP 客户端也能测）**
```powershell
# 起 SSE 版（需网关在跑；API Key 在管理端"API Key"页签发）
$env:AIHUB_API_KEY='ak_你的key'; java -jar aihub\aihub-mcp-sse\target\*.jar
# 另开窗口：SSE 建连，能看到 endpoint 事件
curl.exe -N http://127.0.0.1:8090/sse
```
预期：流里返回 `event: endpoint` 给出 `/mcp/message?sessionId=...`——SSE"双通道"（长连接收、POST 发）当场看见。

**实验 2｜stdio 版手工喂协议（最能建立体感）**
```powershell
'{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"cli","version":"1"}}}' | java -jar aihub\aihub-mcp-stdio\target\aihub-mcp-stdio.jar
```
预期：stdout 吐出一行合法 JSON-RPC capabilities 响应，**且除 JSON 外没有任何杂质**（banner/日志都被刻意清场）。
再把 `tools/list` 请求喂进去，能看到四个工具及说明书全文。

**实验 3｜"错误转人话"复现**
把 `AIHUB_API_KEY` 设成乱值再跑实验 1 的客户端调用（或 MCP Inspector 里调 `aihub_list_applications`）。
预期：工具不报 JSON-RPC error，而是**返回一段文字**"查询应用列表失败：鉴权未通过（HTTP 401），请检查 aihub.mcp.api-key 是否有效或已吊销"——这就是卡 4 说的面向模型编程。

## 4. 自测五问

1. 新加一个"查用量"工具，要改几个模块？（只改 mcp-service：AiHubApi+HttpAiHubApi+AiHubTools 各加一法，两个传输零改动）
2. stdio 进程里 grep 日志去哪看？（stderr + `${java.io.tmpdir}/aihub-mcp-stdio/aihub-mcp-stdio.log`）
3. 为什么 SSE 版 `annotation-scanner.enabled=false`？（我们走 @Tool+ToolCallbackProvider 原生路线，不关它 mcp-annotations 会全类路径扫 @McpTool 打"没找到工具"的误导 WARN）
4. 客户端连 SSE 版报 401 而 API Key 明明有效？（检查是否开了通道门禁 `aihub.mcp.auth`——那是**连接层** Bearer，和**数据层** X-API-Key 是两道不同的门）
5. MCP 工具返回被截断说明什么？（chunk-max-chars=800 生效，防单工具撑爆上下文，截断有标注属正常设计）
