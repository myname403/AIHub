# 第三轮：记忆卡片与动手实验

## 1. 总口诀

**"两证一簿三家规，两阶段扣三级跳"**

| 口诀 | 含义 |
|---|---|
| 两证 | JWT（人的凭证）、API Key（机器的凭证） |
| 一簿 | 户口本：sys_tenant + sys_user |
| 三家规 | RBAC 三关系表：user_role / role_menu / menu(权限源) |
| 两阶段 | 配额：先全试算、后全累加 |
| 三级跳 | 权限解析：用户→角色→菜单→permission 集合 |

## 2. 六张卡片

**卡 1｜登录六步**：码(验证码)→租(户)→人→密→态→票。防枚举：人不存在和密码错同一文案。
**卡 2｜注册八步写五表，一事务**：租户/用户/角色/角色菜单/用户角色——@Transactional 保"要么全成要么全滚"。
**卡 3｜F 型按钮菜单**：不进路由树、只进权限集合——同一张 sys_menu 喂饱"页面可见性"和"按钮权限"两种需求。
**卡 4｜权限缓存三问**：key 带租户；变更点主动 invalidate（漏敲=幽灵 bug）；TTL 10 分钟兜底；多实例要换 Redis。
**卡 5｜配额三表**：policy 规则 / usage 计数器 / record 流水——扣减读计数器、看板读流水，**永远别让一张表兼两职**。
**卡 6｜period_key 字符串清零法**：day→2026-10-06 新一天新行，**零定时任务**——"用数据模型消灭调度"的经典思路。

## 3. 动手实验（都在你现成的环境里做）

**实验 1｜注册的事务边界（最有教学价值）**
1. 用户端注册一个新租户（比如 code=`t1`）；
2. 查库：`docker exec aihub-mysql mysql -uroot -proot123456 -t -e "select * from aihub_platform.sys_tenant where code='t1'; select count(*) from aihub_platform.sys_role_menu rm join aihub_platform.sys_role r on rm.role_id=r.id;"` → 五表数据齐全；
3. 思考：若第⑥步建角色后断电，没有事务你会看到什么？（有租户没角色的"残废租户"——登录成功、菜单全空、接口全 403，正是 V9 迁移给 demo 补过的历史事故）。

**实验 2｜权限缓存的"时差"**
1. demo 管理员登录管理端 → 新建角色（不授权任何菜单）→ 给自己绑上 → 立刻刷新：菜单应该消失（assignRoles 里敲了 invalidateUser）；
2. 反向验证：直接 `UPDATE sys_menu SET status=0 WHERE id=<某菜单>`（绕过服务改库）→ 前端**最多 10 分钟才生效**——缓存只被"业务变更"失效，绕过应用改库它不知道。这就是"缓存一致性"的体感课。

**实验 3｜配额两阶段**
```sql
-- 给 demo 租户配一个"次数日限=3"
INSERT INTO aihub_platform.ai_quota_policy (id, tenant_id, dimension, period, limit_value)
VALUES (999001, 1001, 'request', 'day', 3);
```
用户端连发 4 次对话 → 第 4 次应报配额错误；再查 `ai_quota_usage`（used_value 停在 3）和
`ai_usage_record`（流水只有 3 条）——**试算不过连流水都不留**，两阶段的直观证据。
玩完删掉这条策略恢复正常。

**实验 4｜Flyway 不可改历史**
试着把 V1 里 demo 租户名改成别的再重启 platform → 启动直接失败（checksum mismatch）。
正确姿势永远是：新增 V11。改完记得改回来（或删掉 target 里的旧 class 重新编译恢复原文件）。

## 4. 自测六问

1. 管理端为什么没有"创建租户"功能？（注册即建租户，管理端只管租户内）
2. `selectByTenantAndUsername` 里为什么手写 `deleted=0`？（@Select 原生 SQL 不走 MP 的 @TableLogic 自动拼接）
3. 用户 A 被停用，他的 JWT 还能用吗？用到什么时候？（网关验签不看库——能用到过期≤2h；但业务接口在登录态/权限查询时无碍，**真正的即时拉黑需要黑名单机制**，这是无状态 JWT 的已知代价）
4. 为什么 sys_role_menu 在租户 SQL 兜底白名单里？（它是"角色↔全局菜单"的授权关系，无 tenant_id 列）
5. 配额扣减的并发超扣窗口注释承认了，生产怎么根治？（Redis 原子扣减+Lua，或 SELECT FOR UPDATE；教学项目取简单）
6. InternalController 的接口会不会被外部直接调？（网关路由不放行 /internal/**，且服务端口不对外——但 standalone 直连模式下是敞的，已知边界）
