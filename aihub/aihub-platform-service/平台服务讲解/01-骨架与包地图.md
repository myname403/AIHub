# 第一轮：骨架与包地图

> 目标：65 个类看着多，其实每个包都是同一个套路四件套：**Controller → Service → Mapper → Entity(DO/VO)**。
> 学会认"人设"，新类一律先问它属于哪个包、扮演四件套里的哪个角色。

---

## 1. 一个业务包的标准解剖（以 apikey 为例）

```
apikey/
├── controller/ApiKeyController.java   收 HTTP、参数校验、调 Service（不写业务！）
├── service/ApiKeyService.java         业务规则（签发限额、吊销校验、租户从上下文取）
├── mapper/SysApiKeyMapper.java        DAO——空接口也全能（MyBatis-Plus BaseMapper）
└── entity/SysApiKeyDO.java            表映射（一行 = 一把 Key）
```

**认类三步法**：看包名（管哪摊事）→ 看后缀（Controller/Service/Mapper/DO/VO，扮演什么角色）→ 看类注释（这个项目每个类都有"作者自述"，先读它，90% 的疑惑它直接回答）。

两个后缀必须分清：
- **DO**（Data Object）= 数据库一行，**绝不允许出现在 Controller 签名里**；
- **VO**（View Object）= Web 层收发，入参带 `@NotBlank` 校验注解、出参按前端需要裁剪（**passwordHash 在 DO→VO 转换时天然被丢弃**，不靠"记得手动置空"）。

## 2. 七个包的人设卡

| 包 | 人设 | 核心类 | 一句话职责 |
|---|---|---|---|
| auth | 发证窗口 | AuthController / **AuthService** / CaptchaService | 登录 6 步、注册 8 步（第二轮逐帧讲） |
| tenant + user | 户口本 | SysTenantDO / SysUserDO / SysUserMapper | 租户与用户两张主表；`selectByTenantAndUsername` 是隔离的样板 SQL |
| system | 家规(RBAC) | **PermissionService** / SysUserService / SysRoleService / SysMenuService / @RequirePermission + PermissionInterceptor | 角色-菜单-权限三张关系表 + 注解式鉴权 |
| apikey | 门禁卡房 | ApiKeyService / ApiKeyController | 签发（明文只出现一次）/列表/吊销；给网关反查用 |
| quota | 计费闸门 | **QuotaService** / UsageQueryService | 策略+计数器+流水三表；两阶段扣减 |
| internal | 内网后门 | InternalController | 实现 aihub-api 的 PlatformClient 契约，只给 AI 服务 Feign 调 |
| config + security | 水电煤 | WebMvcConfig / CryptoConfig / MybatisPlusConfig / **JwtTokenProvider** | 拦截器注册、BCrypt Bean、MP 分页与租户兜底、JWT 签发 |

## 3. 十张表分家（对着表名记职责）

```
身份：sys_tenant(租户) ──< sys_user(用户, uk_tenant_username 租户内唯一)
家规：sys_role(角色,每租户一份) ── sys_user_role(用户↔角色)
     sys_menu(菜单,平台全局定义!) ── sys_role_menu(角色↔菜单)
凭证：sys_api_key(存哈希不存明文)
配额：ai_quota_policy(规则) / ai_quota_usage(计数器) / ai_usage_record(流水)
```

三个"表名里的设计思想"：
1. **sys_menu 没有 tenant_id**——菜单是平台全局定义的，租户只"授权"不"定义"（所以它在租户 SQL 兜底的白名单里）；
2. **usage 计数器 vs record 流水分家**——扣减判断读计数器（快），看板聚合查流水（全）；一张表干两件事两头不讨好；
3. **period_key 是字符串**（day→`2026-10-06`，month→`2026-10`）——新周期自然落新行，**不需要任何定时任务清零**。

## 4. 请求进来先过三道闸（WebMvcConfig）

拦截器注册顺序（order 越小越先）：

```
TraceIdInterceptor（先有链路 ID，后面报错才可查）
  → TenantResolveInterceptor（读 X-Tenant-Id 进 ThreadLocal，缺头即拒）
    → PermissionInterceptor（读方法上的 @RequirePermission，比对权限集合）
```

对应网关讲解的"接力"：网关撕伪造头写可信头 → 这里第一个闸接工牌 → 第三个闸查家规。

## 5. 建表脚本在哪？（Flyway 心智）

`src/main/resources/db/migration/V1__init_platform.sql` 起，V2~V10 增量。
**服务启动时自动按版本号顺序执行未跑过的脚本**，`flyway_schema_history` 表记账。
所以：改表结构=加一个 V11 迁移文件，**永远不改已发布的历史脚本**（checksum 校验会炸——V10 修密码哈希就是绕开改 V1 的正面教材）。
`demo` 租户种子在 V1、RBAC 补种在 V9、密码修正 V10——三段历史本身就写了三个故事。
