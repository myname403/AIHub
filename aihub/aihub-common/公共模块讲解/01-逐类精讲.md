# 第一轮：6 个包 13 个类逐类精讲

> 阅读方式：按包的"故事线"走——先约定响应格式（result），再约定出错怎么办（exception），
> 然后是两大上下文（tenant/trace），最后安全件（security/crypto/web）。
> 每个类四段式：**干什么 → 关键设计 → 不用它会怎样 → 谁在用**。

---

## 包 1｜result —— 全系统"说话的方式"

### R.java —— 统一响应体

所有 HTTP 接口（不管成功失败）返回的 JSON 长一个样：

```json
{ "code": 0, "message": "成功", "data": {...}, "traceId": "a1b2c3d4" }
```

- **关键设计**：私有构造器 + 静态工厂 `R.ok(data)` / `R.fail(ResultCode)`——想造 R 只能走这几个门，保证 code 语义不乱；`traceId` 自动从 TraceContext 取（**响应体里自带链路 ID，前端报错截图=送线索**）；
- **不用它会怎样**：登录接口返回裸对象、用户列表返回 `{list,total}`、报错返回 Spring 默认 500 页——前端每个接口写一套解析；
- **注意**：`code=0` 才是成功，HTTP 状态码恒为 200（业务错误也 200）。网关手写的 401 是例外（HTTP 401 + 同格式 body）。

### ResultCode.java —— 错误码户口本

R 里 code 的合法值清单（枚举）：`0` 成功；`1xxxx` 通用错（参数 10001、未认证 10002、无权限 10003、租户 10004、限流 10006、配额 10007）；`2xxxx` AI 专属；`5xxxx` 系统级。

- **为什么用枚举不用常量**：可读（`UNAUTHORIZED` vs `10002`）、集中管理、编译期防拼错；
- 记忆：**"1 通用、2 智能、5 系统"**，像手机号段。

## 包 2｜exception —— 全系统"出错的方式"

### BizException.java —— 可预期的业务错误

"密码错误""配额不足""跨租户访问"这类**规则不允许**的错，抛它。

- **关键设计**：继承 `RuntimeException`（非受检）——业务层想抛就抛，不用每层签名写 throws，异常一路飞到兜底网；
- **纪律**：message 会原样给前端，**绝不能拼密钥/完整 Prompt/SQL**；
- 不用它：Controller 里全是 try-catch，或者错误格式五花八门。

### GlobalExceptionHandler.java —— 异常兜底网

`@RestControllerAdvice` 把自己变成所有 Controller 的"异常 catcher"：BizException→对应 code；参数校验异常→10001；**其他一切异常→50000"系统内部错误"**（详情只进日志，不外泄）。

- **业务代码因此获得一条极简纪律：该抛就抛，别 try-catch**；
- **边界**：它只管 MVC 服务。**网关（WebFlux）的异常不走它**——这就是网关 AuthGlobalFilter 里手写 401 JSON 的原因（网关讲解第三轮讲过，两边呼应）。

## 包 3｜tenant —— 多租户的"内存储物柜"

### TenantContext.java —— ★全项目最高危约束的载体

ThreadLocal 存"当前请求是谁"（tenantId/userId）。拦截器入口放进，Controller→Service→Mapper 任何深度随手 `getTenantId()` 取，**不用一层层传参**。

- **铁律（注释里三个加粗）**：租户 ID **只允许**从 JWT/API Key 解析后写入，绝不接受前端传参；
- **必须 clear()**：线程池会复用线程，不清理=上一个请求的租户"串台"到下一个请求（重大越权事故）；
- 配套 `requireTenantId()`：取不到直接抛——把"忘了设置"变成当场崩溃而不是静默越权。

### TenantResolveInterceptor.java —— 下游接工牌的人

Servlet 拦截器：`preHandle` 把网关传来的 `X-Tenant-Id` 头写进 TenantContext，`afterCompletion` 清理（一进一出配对）。

- **信任链**：它敢无条件信这个头，因为网关已撕掉客户端伪造值（"边界统一鉴权"：鉴权只做一次，内网互信）；
- **头缺失即拒绝**（fail-fast）——宁可 401 也不带空租户跑业务。

## 包 4｜trace —— 全链路"快递单号"

### TraceContext.java —— ThreadLocal + MDC 双写

一次请求的身份证号（traceId）。存两份：
- **ThreadLocal**：业务代码取值、R 自动填充；
- **MDC**（日志框架的上下文地图）：logback pattern 配 `%X{traceId}` 后**每行日志自动带 ID，业务代码零改动**。

- **坑**：异步/流式场景线程会切换，储物柜拿不到——要显式 `wrap()` 传递（AI 服务流式链路大量用到）。

### TraceIdInterceptor.java —— 下游版盖戳器

和网关 TraceIdGlobalFilter 干同一件事，只是载体从 GlobalFilter 换成 HandlerInterceptor（WebFlux 没有 Servlet）。**注册顺序有讲究：必须在 TenantResolveInterceptor 之前**——租户缺失的报错日志得先有 traceId 可查。

## 包 5｜security + crypto —— 三把不同的"锁"

### JwtVerifier.java —— 验令牌

三段式 `header.payload.signature`：验签+过期检查，不过返回空 Map。**平台负责签发（JwtTokenProvider），这里只管验**。放在 common 是因为有网关过滤器覆盖不到的入口（如 WebSocket 握手）要自己验。

### ApiKeyCodec.java —— 造 Key、验 Key

`ak_` 开头的 API Key：生成（256 位随机值）、**只存 HMAC-SHA256 哈希不存明文**（忘了解析不了，只能重置，GitHub Token 同款策略）。

- **为什么不用 bcrypt**（密码用的慢哈希）：Key 校验发生在每个请求上，bcrypt 的"故意慢"会拖垮吞吐；Key 本身是纯随机值没有弱口令问题，带服务端密钥的 HMAC 足够——拖库者没密钥也伪造不出 Key。

### AesGcmTextCipher.java —— 加密存密

给"必须能还原"的敏感数据用（如用户的模型 API Key 落库）。**GCM 是认证加密**：密文被篡改一位解密直接失败（不是返回乱码），自带完整性校验；每次加密随机 IV，同一明文密文不同（防彩虹表）。

**三把锁分工记忆**：

| 类 | 锁的方向 | 可逆吗 | 场景 |
|---|---|---|---|
| JwtVerifier | 验令牌 | — | 用户身份 |
| ApiKeyCodec | 单向哈希 | ❌ | 平台发的 Key，只比对不还原 |
| AesGcmTextCipher | 双向加密 | ✅（有密钥） | 第三方 Key 要原文拿去调模型 |

## 包 6｜web —— 一个"补丁"类

### JacksonLongToStringConfig.java —— 雪花 ID 精度救星

JS 的 Number 是双精度浮点，只装得下 2⁵³-1（16 位）；雪花 ID 19 位，JSON 数字下发**末几位被四舍五入抹平**（`...992123` 变 `...992000`），前端回传就"id 对不上"。解法：全局把 Long 序列化成**字符串**，前端原样回传，后端反序列化无感。

- **作用范围**：MVC 服务的响应 ObjectMapper；网关（WebFlux）不受影响；
- 这是"数据没错、是 JS 装不下"的经典事故的全局修法。

## 依赖关系收尾（为什么谁都能用它）

```
aihub-common（不依赖任何业务模块）
   ▲           ▲            ▲
platform-service   ai-service   gateway(部分类)   mcp(刻意不用!见下)
```

**反例教材**：`aihub-mcp-stdio` 宁可不依赖 common 也要避开它传递的 servlet 容器依赖（stdio 进程里 Tomcat 纯属负担）——common 好用，但"什么都往里塞 starter-web"的代价就是有人想轻都轻不了。这也是为什么 mcp 模块自己镜像了一份 `ApiEnvelope` 而不是复用 R。
