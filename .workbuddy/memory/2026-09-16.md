## 本次调研发现的「文档与代码不一致」（重要，之前没记录）

子代理挖出 10 条，已写进 09 的照妖镜与 12：

### 后端
1. **配额 task 维度真正拦截**：`consumeAgentTask` 原来忽略 `allowed`，改为与 request/doc 一致
   （同步抛 `QUOTA_EXCEEDED` / 流式发 error 事件），降级放行语义保留。
   平台侧已确认「未配置策略的维度直接放行」，所以不会误伤无 task 策略的租户。
2. **Outbox 落地**（`ai_event_outbox` 从零实现）：
   `domain/spi/EventOutbox` + `infra/outbox/DbEventOutbox`（落库，失败只记日志）
   + `infra/outbox/EventOutboxDispatcher`（单线程守护线程，30s/批 50/max-retry 3，
   无 `@EnableScheduling`——与 CdpBrowserSessionManager 保持同一风格）。
   ★ **关键坑**：后台线程无请求上下文，而 `FeignTenantConfig` 只在租户非空时写
   `X-Tenant-Id`，平台 `TenantResolveInterceptor` 又强制要求该头 →
   **投递前必须按事件的 tenant_id 临时 `TenantContext.set` 并在 finally 清理**，否则重投 100% 失败。
   `ChatAppService.reportUsage` 失败时改为 `eventOutbox.enqueue`。
3. **租户 SQL 兜底（第五道防线）**：`TenantSqlGuardConfig`（ai-service，@ConditionalOnProperty）
   与 `MybatisPlusConfig`（platform，加在既有 bean 内）。`TenantLineInnerInterceptor`
   + 白名单（ai：`ai_model_provider`；platform：`sys_tenant`/`sys_menu`/`sys_role_menu`）
   + **无租户上下文即 ignoreTable=true**（登录/异步/内部接口行为不变）。
   **默认关闭** `aihub.tenant.sql-guard.enabled=false`：单测 mock 覆盖不到真实 SQL 改写，
   未在真库验证不做默认值。开启步骤写在类注释与 `aihub/README.md` 6.1。
4. **四处小缺陷**：PlanningAgent finally 兜底终态（防 NPE 覆盖原错）；
   `initialize-schema` 配置真正生效；`browser.max-steps` 改由自身配置决定
   （原被规划层共享预算 3 压成 3 步）+ 新增回归用例；
   `ModelEndpoint.openAiCompatible()` 补 ollama 并在 resolver 里做快速失败。
5. **ArchUnit 4 → 7 条**：domain 收紧到禁全部 `org.springframework..`/`com.fasterxml..`；
   application 禁 Spring AI/ORM/Redis；web 禁 ORM；新增「底层 infra 不得反向依赖 AI 层」
   「AI 层不得依赖 browser 实现」「browser 不得碰 persistence」。
   加规则前先 grep 校验现状，避免误伤（`infra/browser/BrowserConfiguration` 依赖 `infra.ai`
   是其装配职责，故方向是 browser→ai 合法）。
