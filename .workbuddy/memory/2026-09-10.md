## 项目差距审查（文档承诺 vs 代码落地）
对 README + docs/01~07 的里程碑 DoD 与 M0~M5 任务清单，逐条比对实际 Java / DDL / 前端代码，输出差距清单。

**完成度估算**：M0 9/10、M1 5/7、M2 5/8、M3 2/6（最差）、M4 5/9、M5 2/6（最差）

### 已确认的真实缺陷 / 违规
1. `ChatAppService`（application 层）引用 `com.aihub.ai.infra.ai.agent.PlanningAgent.NAME`
   → 违反 ArchUnit 规则「application 不得依赖 infra」；只因 `static final String` 常量被编译期内联，
   字节码无类引用才逃过检测。修复：在 domain 建 `AgentNames.PLANNING` 常量。
2. `QuotaService.checkAndConsume` 的比较器 `(a,b) -> "day".equals(a.getPeriod()) ? -1 : 1`
   不满足传递性，策略 >2 条时可能抛 `Comparison method violates its general contract`。
3. `QuotaService.currentUsed` 按 appId 累加（`upsertConsume` 传 appId）但查询未带 appId 条件 → 跨应用混算。
4. `ChatAppService.reportUsage` 的 tokenIn/tokenOut/modelCode 全传 null → M1 DoD「每次调用落 Token 与耗时」未达成，
   用量看板无数据可用。

### 文档有、代码无
- M1：无审计 Advisor、无 `StreamAroundAdvisor`（文档 R9 风险明确要求双路径）；Advisor 链只有 MessageChatMemoryAdvisor。
- M2：无 `ai_message_reference` 表 → 引用不落库，刷新页面引用丢失；`ai_ingest_task` 表存在但入库是同步串行的
  （无异步 / 进度 / 重试）；无跨租户自动化测试用例（只有 ArchUnit 4 条，0 业务单测）。
- M3：`spring-ai-starter-mcp-client` 依赖已引入但**零集成代码**（全仓无 ToolCallback / McpSyncClient 引用）；
  `ai_tool` / `ai_mcp_server` 表无对应实现；工具只有 TimeTools 一个，无调用审计 `ai_tool_call_log`。
- M4：`ai_agent_task` / `ai_agent_step` 表无写入 → 无 checkpoint / 恢复；「停止」只是前端 `uni.request.abort()`，
  服务端循环不感知（M4 DoD「后续步骤真正取消」未达成）；三重预算只有 maxSubTasks，缺 maxToken / maxTimeout。
- M5：配额只有 request 维度（缺 token / document / task）；无 Micrometer 指标、无 TraceId 全链路、无 API Key、
  无用量查询接口与看板页面。

## 已完成的补齐（同日，全部编译通过 BUILD SUCCESS）
测试统计：common 4 / platform 5 / ai-service 14（ArchUnit 4 + AgentBudget 5 + TextChunker 5）

### P0 缺陷修复
- 新增 `domain/model/AgentNames`（PLANNING/TABLE/CHART/HTML），四个 Agent 的 `name()` 改引它；
  `ChatAppService` 不再 import infra（架构违规消除）。顺手清理了 ChatAppService 里一堆全限定名硬编码。
- `QuotaService`：comparator 改 `Comparator.comparing(p -> !"day".equalsIgnoreCase(p.getPeriod()))`；
  **且必须先 `new ArrayList<>(policies)` 再 sort** —— 单测发现 `List.of()` 返回的不可变列表原地 sort 会抛
  UnsupportedOperationException（这是写代码时没想到的真实隐患）。
  配额口径统一为租户级（`upsertConsume` 与 `currentUsed` 都用 appId=null + `isNull(appId)`），
  因为 `ai_quota_policy` 无 app_id 列；应用明细仍记在 `ai_usage_record.app_id`。
- Token 统计：`ChatExecutor.StreamResult` 增加 tokenIn/tokenOut；`SpringAiChatExecutor` 流式改用
  `.stream().chatResponse()`（usage 在最后一个 chunk）、同步用 `.call().chatResponse()`；
  `ChatAppService.reportUsage` 传真实值。
- 新增 `infra/ai/AuditAdvisor`：**Spring AI 1.1.5 没有 CallAroundAdvisor/StreamAroundAdvisor**，
  正确接口是 `org.springframework.ai.chat.client.advisor.api.CallAdvisor` / `StreamAdvisor`
  （`adviseCall(ChatClientRequest, CallAdvisorChain)`、`adviseStream(...)`；`Advisor extends Ordered`）；
  另有 `BaseAdvisor` 接口提供 before/after 模板。审计只记元数据，不记正文。

### M3 工具与 MCP
- MCP 真集成：`ChatClientFactory` 注入 `ObjectProvider<ToolCallbackProvider>`，
  用 `orderedStream()` 收集 MCP starter 装配的工具，与内置工具一起经 `AuditedToolCallback` 包装后
  `defaultToolCallbacks(list)` 挂载。未配 MCP 时自动降级为仅内置工具。
- yml 关键坑：`spring.ai.mcp.client.toolcallback.enabled` 必须为 true，否则 MCP 工具不生效。
- 新增工具 `KnowledgeTools`（Agentic RAG：模型自主检索当前应用绑定的知识库），
  租户/应用上下文由新增的 `AiCallContext`（ThreadLocal，infra-ai 内部）提供。
- 工具调用审计：新增 `ai_tool_call_log`（V4 SQL）+ `ToolCallLogStore` SPI + `DbToolCallLogStore`。

### M4 Agent 健壮性
- `AgentBudget`（子任务数 / Token / 超时，`AtomicLong.addAndGet`——注意 AtomicLong 没有 add()）；
  `AgentTask` 增加 budget 字段并在 `subTask` 中共享；`AgentBudgetExceededException`；
  `BaseAgent.llm(AgentTask,...)` 调用前后校验预算并累加 token。
- 落库：`AgentTaskRepository` SPI + `DbAgentTaskRepository` + `ai_agent_task/ai_agent_step`
  （V5 补 user_id/used_tokens/cost_ms/answer/agent_name 列）。
- 中断：`AgentCancelRegistry` + `InMemoryAgentCancelRegistry` + `POST /api/ai/agent/cancel`；
  前端 stop() 先调取消接口再 abort。结果状态新增 `AgentResult.CANCELED`。
